## Что именно проверяется

Четыре правила. Ни одно из них не ловится существующими скриптами: `readability_flags.py`
меряет длину предложений, длину абзацев, аббревиатуры и капс, а это другое.

| правило | нарушение выглядит так | как должно быть |
|---|---|---|
| §2.6 | «`IntersectionObserver` — это API для отслеживания пересечений» | «Браузер сам сообщает, когда элемент попал в видимую часть страницы; этот механизм называется `IntersectionObserver`» |
| §7.7 | `## Fixed timestep vs variable timestep` | `## Фиксированный шаг времени против переменного` |
| §3.6 | абзац, где каждое предложение несёт новый факт и ни одно не связано с соседним | абзац читается как объяснение живого человека |
| §3.6 | «Рассмотрим устройство X. Он состоит из…» | сначала зачем нужен и какую проблему решает, потом как устроен |

Плюс два запрета оттуда же: абстрактные `foo`/`bar` вместо жизненных примеров и опора на
контекст, которого у читателя нет («как мы уже выяснили», «очевидно»).

**Главный критерий — вопрос, а не метрика.** Прочитай текст глазами человека, который вернулся
к теме через полгода. Место, где он остановится и полезет вспоминать, что значит слово, и есть
находка.

## Границы проверки: что НЕ трогаем

- **Технический смысл.** Упрощается язык, а не концепции (§1). Senior-глубина — ценность сайта.
- **Детали, оговорки, крайние случаи, версии и числа.** Их нельзя убирать ради гладкости.
- **Код в примерах.** Поведение примеров не меняется.
- **Структура зоны.** Файлы не переименовываются, не сливаются и не переставляются.
- **Английские имена там, где они и есть название.** `OnPush`, `storageState`, `getByRole` —
  остаются латиницей, но с русским пояснением при первом употреблении.

## Шаг 2. Прогнать механическую проверку

Скрипт `scripts/audit/language_accessibility.py` показывает кандидатов по §2.6, §7.7 и §3.6.

```bash
python3 scripts/audit/language_accessibility.py content/topics/<ЗОНА>/ru
python3 scripts/audit/language_accessibility.py content/questions/<ЗОНА>.json
```

Как его читать:

- **Он фокусирует, а не выносит приговор.** Каждый кандидат подтверждается или отклоняется
  чтением. На зоне `playwright`, написанной уже по этим правилам, он даёт ноль кандидатов; на
  `canvas-graphics`, написанной до них, — несколько десятков.
- **Английскую локаль он пропускает**, потому что построен на соотношении латиницы и кириллицы.
  Её проверяют чтением по тому же правилу «объяснение раньше термина» и сверяют по составу с
  русской (§8.3: ни одна локаль не несёт факта, которого нет в другой).
- **Ноль кандидатов не значит «всё хорошо».** Порядок «зачем → как», связность абзаца и
  абстрактность примеров скрипт не видит вовсе.

Заодно сними базовые метрики, чтобы потом доказать, что правки ничего не сломали:

```bash
python3 - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, 'scripts/audit')
import readability_flags as rf
for loc in ('en', 'ru'):
    d = Path('content/topics/<ЗОНА>', loc)
    if not d.exists():
        continue
    for p in sorted(d.glob('*.md')):
        t = p.read_text(encoding='utf-8'); pr = rf.to_prose(t)
        print(loc, p.name,
              len(rf.find_abbreviations(pr, loc)),
              len(rf.find_long_sentences(t, loc)),
              len(rf.find_long_paragraphs(rf.blocks_of(t))),
              rf.count_caps_emphasis(pr))
PY
```

**`readability_flags.py` с аргументом пути запускать нельзя** — он перезаписывает закоммиченные
`audit/readability_flags.json` и `audit/readability-flags.md`.

## Шаг 3. Прочитать зону

Это основная часть работы, и пропустить её нельзя: три правила из четырёх не детектируются.

Читай подряд, файл за файлом, и на каждом абзаце спрашивай себя три вещи:

1. **Появился ли здесь термин раньше, чем смысл?** Ищи конструкции «X — это…», «используется
   X», «через X», где X не объяснён выше. Отдельно смотри первые абзацы файлов: читатель часто
   приходит из поиска сразу туда.
2. **Этот абзац объясняет или перечисляет?** Признак перечисления: предложения можно менять
   местами без потери смысла.
3. **Порядок «зачем → как» соблюдён?** Если раздел открывается устройством механизма, а не
   задачей, которую он решает, это находка.

Отдельно пройди по заголовкам: `grep -n "^#" content/topics/<ЗОНА>/ru/*.md`. Заголовок из
английских слов — находка даже тогда, когда каждое слово знакомо.

## Шаг 4. Отчёт

Формат: сводка, затем таблица находок, затем предложения. Никаких правок на этом шаге.

```markdown
## Зона `<ЗОНА>`: доступность языка

Файлов проверено: N статей (ru), M записей банка. Кандидатов от скрипта: K,
подтверждено чтением: L. Метрики до правок: флагов X, широких строк Y.

| файл:строка | правило | как сейчас | предлагаю |
|---|---|---|---|
| `03-pixels.md:72` | §2.6 | «Используем ImageData для доступа к пикселям» |
  «Чтобы добраться до пикселей, картинку превращают в массив чисел; он
  называется `ImageData`» |
| `04-webgl.md:1` | §7.7 | `# WebGL и основы GPU` | `# WebGL: как рисовать на видеокарте` |

Сводка по типам: §2.6 — N, §7.7 — M, §3.6 — K, прочее — L.
Файлы в худшем состоянии: …
```

Требования к отчёту:

- **Каждая находка с путём и строкой**, чтобы её можно было проверить.
- **Цитата дословная**, а не пересказ.
- **Предложение конкретное**, а не «переписать понятнее».
- **Отдельно назови места, где текст непонятен по существу**, а не по форме: если абзац нельзя
  переформулировать, не разобравшись в предмете, это другой класс работы, и его надо назвать.
- **Если зона чистая — так и скажи**, с числами. Отчёт без находок тоже результат.

## Шаг 5. Правки — только после подтверждения

Когда я подтвержу список, правь по файлам, небольшими порциями, и после каждого файла меряй.

- **Правки пишутся питон-скриптами через Bash, не `Edit`/`Write`** — вкладки-диффы съедают
  память IDE и уже останавливали агентов. Скрипт с кириллицей — через heredoc либо с
  `# -*- coding: utf-8 -*-` в первой строке.
- **Каждая замена — точечная, с проверкой уникальности** (`assert t.count(old) == 1`).
- **После каждого файла сверяй метрики с базовыми.** Частая ловушка: объяснение перед термином
  удлиняет предложение за лимит 28 слов, а новое строчное слово превращает соседний акроним в
  «крик».
- **Изменил смысл в одной локали — зеркаль во вторую** (§8.3), иначе локали разъедутся.
- **Менял H1 — проверь подписи ссылок:** в русской локали подпись внутризонной ссылки берётся
  из H1 целевого русского файла. Вот проверка:

```bash
python3 - <<'PY'
import re
from pathlib import Path
for loc in ('ru', 'en'):
    base = Path('content/topics/<ЗОНА>', loc)
    if not base.exists():
        continue
    h1 = {p.name: p.read_text(encoding='utf-8').splitlines()[0].lstrip('# ').strip()
          for p in base.glob('*.md')}
    for p in sorted(base.glob('*.md')):
        for label, target in re.findall(r'\[([^\]]+)\]\(\./([\w-]+\.md)\)',
                                        p.read_text(encoding='utf-8')):
            label = ' '.join(label.split())
            if target in h1 and label != h1[target]:
                print('MISMATCH', loc, p.name, '->', target)
                print('   подпись:', label)
                print('   H1:     ', h1[target])
PY
```
