## Что это за зона

`Web API` — набор возможностей, которые браузер даёт приложению: наблюдатели за элементами,
фоновые потоки, хранилища, связь между вкладками, файлы, потоки данных, разрешения. Зона новая:
статей по ней на сайте нет.

- **id:** `web-api`
- **label:** `Web Platform APIs`
- **level:** `medium`
- **Файлов:** 9 статей + файл вопросов = **10 файлов на локаль, 20 всего**. Типичный размер
  зоны по сайту — 14–24 файла, 7–35 тысяч слов.

## Стиль: правила из `CLAUDE.md` действуют буквально

Они же продублированы в контракте — §2.6, §3.6 и §7.7 `content/STYLE.md`. Самое важное для
этой зоны, где английских имён много:

- **Термин сначала объясняется обычными словами, и только потом называется по-английски.**
  Плохо: «`IntersectionObserver` — это API для отслеживания пересечений». Хорошо: «Браузер сам
  сообщает, когда элемент появился в видимой части страницы; этот механизм называется

- **Заголовки разделов — русские и осмысленные.** Плохо: «Structured clone algorithm». Хорошо:
  «Что можно передать в фоновый поток, а что нельзя».
- **Абзац читается как объяснение живого человека**, а не как выжимка из справочника. Механизм
  подаётся в порядке «зачем он нужен → какую проблему решает → как устроен».
- **Примеры жизненные.** Лента заметок, вложение в письме, вторая вкладка того же приложения —
  да. `foo`, `bar`, `doSomething()` — нет.
- Перед сдачей перечитай файл глазами человека, который вернулся к теме через полгода. Место,
  где нужно остановиться и вспоминать термин, переписывается.

**Отдельно про H1 и подписи ссылок.** Подпись внутризонной ссылки обязана совпадать с H1
целевого файла, поэтому H1 разъезжается по всем девяти файлам. Отсюда правило: **не ставь в H1

## Версии и факты

**Ничего не выдумывай про поддержку браузерами.** У Web API это главный источник вранья: часть
возможностей есть только в Chromium, часть за флагом, часть переименована. Сверяй с
документацией и с таблицами поддержки, а где уверенности нет — пиши «на момент написания» и
указывай, где читатель проверит актуальный статус.

Особенно проверь, а не вспоминай: что именно попадает в структурное клонирование и что
передаётся через `Transferable`; какие события жизненного цикла страницы существуют и в каком
порядке приходят; что возвращает `navigator.storage.estimate()`; какие состояния бывают у
разрешения; чем `SharedWorker` отличается от `Worker` по поддержке; какие ограничения у Web
Locks и у File System Access.

**Лучший способ не соврать — прогнать пример в настоящем браузере.** В зависимостях проекта
Playwright нет, поэтому стенд поднимается во временном каталоге за пару минут:

```bash
mkdir -p /tmp/webapi-demo && cd /tmp/webapi-demo
npm init -y && npm i -D @playwright/test
npx playwright install chromium
```

Дальше маленькая страница на локальном сервере плюс тест, который печатает то, что реально
вернул браузер:

```ts
// снять поведение API и вставить настоящий вывод в статью
import { test } from '@playwright/test';

test('что отдаёт storage.estimate()', async ({ page }) => {
  await page.goto('http://localhost:3000/');
  const info = await page.evaluate(() => navigator.storage.estimate());
  console.log(info);
});
```

Настоящий вывод в статье ценится выше пересказа (§6.4). Так делалась зона `playwright`:
поднимался стенд, тесты печатали ответ браузера, и в статью попадал снятый вывод, а не
правдоподобный. Заодно это ловит ошибки памяти: несколько утверждений про формат сообщений
там оказались неверными и были переписаны по факту.

Важная оговорка про такой стенд: он показывает поведение **одного** браузера на **одной**
системе. Вывод `navigator.storage.estimate()` на macOS в Chromium не доказывает, что то же
самое вернёт Firefox. Пиши, где именно снято, если число зависит от среды.

## Терминологические развилки — зафиксированы здесь, до генерации

Проверено на прошлых зонах: развилку, не заданную заранее, приходится рассылать по ходу, иначе
зона раскалывается по §7.6. Формы ниже согласованы с корпусом, где он уже определился.

| английский | русская форма |
|---|---|
| observer | **наблюдатель** (`MutationObserver` и прочие имена остаются латиницей) |
| callback | **колбэк** (в корпусе 46 против 2 у «коллбэк») |
| worker | **воркер** для процесса прогона; для браузерного — **фоновый поток**, далее `Worker` |
| service worker | **сервис-воркер** с пояснением при первом употреблении |
| main thread | **главный поток** |
| origin | **источник (origin)** при первом употреблении, дальше `origin` |
| structured clone | **структурное клонирование** |
| transferable object | **передаваемый объект** |
| scope (у сервис-воркера) | **область действия** |
| quota | **квота** |
| eviction | **вытеснение** |
| stream | **поток данных** (не путать с фоновым потоком: там **поток выполнения**) |
| backpressure | **обратное давление (backpressure)**, дальше `backpressure` |
| polling | **опрос** |
| bfcache | **кэш обратного перехода (bfcache)**, дальше `bfcache` |
| permission | **разрешение** |
| user gesture | **жест пользователя** |

Апострофных склонений не бывает: не `Worker'ы`, а «фоновые потоки». Изобретённых транслитераций
при живом русском слове тоже: не «обсервить», не «поллить», не «эвиктить» — «наблюдать»,
«опрашивать», «вытеснять».

## Сквозной пример на всю зону

Один и тот же продукт во всех девяти статьях: **библиотека заметок с вложениями**. Она выбрана
потому, что в ней естественны все девять тем, и читателю не приходится каждый раз заново
понимать предметную область.

- Лента заметок с подгрузкой при прокрутке.
- Боковая панель с изменяемым размером и оглавлением.
- Поиск по большому тексту и подсветка — тяжёлая работа, которой не место в главном потоке.
- Офлайн-режим: заметки открываются без сети.
- Вложения: картинки и файлы, которые перетаскивают в заметку или вставляют из буфера обмена.
- Несколько вкладок приложения открыты одновременно, и правки должны сходиться.
- Импорт большого архива заметок с возможностью отменить.
- Напоминания, которым нужно разрешение пользователя.

Заводить новый пример на статью нельзя — это лучшая практика сайта, взята из темы `build-tools`.

**Названия внутри примера держи короткими.** Это не вкусовщина: имена попадают в вывод
инструмента, а строка в фенсе `txt` ограничена 68 колонками. В зоне `playwright` пришлось
переименовывать задачи и тесты задним числом, когда снятый вывод не влез в бюджет. Заголовок
заметки «Отчёт за май» безопаснее, чем «Собрать отчёт за май за прошлый квартал».

## План статей

Каждая статья — по шаблону из `TOPIC.md`: H1, лид с ответом в первом предложении, H2-утверждения,
опора (диаграмма, код или таблица) каждые 2–3 абзаца и **выше** объясняющего её абзаца.

1. **`01-platform-model.md` — Что даёт браузер приложению и по каким правилам.**
   Почему возможности платформы приходят объектами `window` и `navigator`, а не импортами. Три
   вещи, которые ограничивают любой Web API: источник (origin), безопасный контекст и жест
   пользователя. Почему почти всё асинхронно. Проверка доступности возможности вместо проверки
   браузера. Диаграмма уровней доступа. Первый работающий пример на ленте заметок.

2. **`02-observers.md` — Браузер сам сообщит, когда что-то изменилось.**
   Почему опрос в цикле проигрывает подписке. Четыре наблюдателя и их разные задачи:
   `IntersectionObserver` для видимости, `ResizeObserver` для размеров, `MutationObserver` для
   изменений разметки, `PerformanceObserver` для измерений. Когда колбэк вызывается и в каком
   потоке. Отписка и утечки. Таблица «что наблюдать чем». Диаграмма момента срабатывания.

3. **`03-workers.md` — Тяжёлая работа уходит с главного потока.**
   Что именно блокирует интерфейс и почему. `Worker` как отдельный поток выполнения со своим
   окружением: что там есть, а чего нет. Обмен сообщениями, структурное клонирование, передаваемые
   объекты и их цена. `SharedWorker` и когда он оправдан. Worklets назвать и очертить. Диаграмма
   «что копируется, а что передаётся». Поиск по заметкам как сквозной пример.

4. **`04-service-worker.md` — Сетевой посредник, который живёт отдельно от страницы.**
   Чем сервис-воркер отличается от фонового потока. Жизненный цикл: установка, активация,
   ожидание, `skipWaiting` и `clients.claim`. Область действия и почему она решает всё. Обновление
   и типичная ловушка «пользователь сидит на старой версии». Отладка. Диаграмма жизненного цикла.
   **Границу с зоной `web-performance` держи:** стратегии кэширования разобраны там, здесь —
   устройство и жизненный цикл.

5. **`05-storage.md` — У браузера несколько хранилищ, и они не взаимозаменяемы.**
   Web Storage, `IndexedDB`, Cache Storage: что синхронно, что переживает перезагрузку, что видно
   сервис-воркеру. Квоты, оценка занятого места, вытеснение и постоянное хранилище. Почему
   `localStorage` блокирует главный поток. Таблица выбора. Черновики заметок как пример.

6. **`06-cross-tab.md` — Две вкладки одного приложения должны договориться.**
   Способы связи: `BroadcastChannel`, событие `storage`, `postMessage` между окнами,
   `SharedWorker` как общий канал. Web Locks и задача «только одна вкладка синхронизирует».
   Выбор лидера. Диаграмма «кто кого слышит». Ловушка: сообщение не приходит самому отправителю.

7. **`07-files-and-clipboard.md` — Файл попадает в приложение четырьмя разными путями.**
   Выбор файла, перетаскивание, вставка из буфера обмена, File System Access. `File` и `Blob`,
   чтение, ссылки на объект и их освобождение. Буфер обмена: чтение требует разрешения, запись —
   жеста пользователя. Скачивание результата. Таблица путей и их ограничений. Вложения в заметку.

8. **`08-streams-and-cancellation.md` — Большие данные обрабатываются по кускам, и работу можно прервать.**
   Почему «дождаться целиком» не всегда возможно. `ReadableStream`, `WritableStream`,
   `TransformStream` и что такое обратное давление. `AbortController` и `AbortSignal`: отмена,
   тайм-аут, связывание сигналов. Что происходит с уже начатой работой. Импорт большого архива
   заметок как сквозной пример. Диаграмма движения данных.

9. **`09-lifecycle-and-permissions.md` — Страница не всегда жива, а разрешение можно и не получить.**
   Состояния страницы и события перехода между ними: скрытие, заморозка, восстановление, bfcache.
   Почему `unload` больше не годится и что вместо него. Отдать главный поток: `requestIdleCallback`
   и разбиение работы. Разрешения: три состояния, проверка без запроса, отказ навсегда.
   Напоминания в заметках как пример. Таблица «событие → что делать».

10. **`10-web-api-interview-questions.md` — Вопросы для интервью.**
    §3.5: **тот же стандарт, что у статей.** Это место, где проход спотыкался чаще всего — в 19
    зонах из 31 самый абстрактный файл зоны был подан сплошной прозой. Чередуй текст с кодом,
    диаграммой или таблицей каждые 2–3 абзаца. Сверься с банком `browser-runtime`: не повторяй
    его вопросы дословно, бери те же темы под другим углом. Хороший образец формы — файл
    `content/topics/playwright/ru/10-playwright-interview-questions.md`: группы вопросов, после
    каждой — блок уточняющих вопросов.

Про стены теории (`find_theory_walls`): она считает списки и заголовки нейтральными, прогон
сбрасывают только код, диаграмма и таблица. Гнаться за нулём там не обязательно, но ритм
«идея → опора → идея» держать надо.

## Процесс — он даёт большую часть качества

- **Диаграммы только программно.** Импортируй билдеры из `scripts/ascii-diagrams/diagram_gen.py`
  как библиотеку (`box`, `layered`, `vchain`, `hstack`, `vstack`, `table`, `with_title_and_notes`)
  и вставь вывод. **Сам `diagram_gen.py` можно только дополнять**, никогда не переписывать: один
  агент однажды снёс оттуда 2623 строки. Нужен новый билдер — добавь функцию и запись в
  `DIAGRAMS`/`LABELS`, с метками для обеих локалей.
- **Ширина диаграммы ≤ 68 колонок.** Соединитель не ставится в грань бокса: `└────┬────┘` даёт
  FAIL. Связь рисуется отдельными строками ниже грани — это делает `vchain()`. И `└` вне бокса
  валидатор считает орфанным углом, так что нарисованную стрелку возврата поставить нельзя.
- **Одна статья за раз, с подтверждением перед следующей.**
- **Пиши питон-скриптами через Bash, не `Edit`/`Write`:** вкладки-диффы съедают память IDE и уже
  останавливали агентов. Скрипт с кириллицей в теле — через heredoc либо с
  `# -*- coding: utf-8 -*-` в первой строке.
- **Меряй после каждой статьи, а не в конце.** Правка часто создаёт новый флаг: глосса удлиняет
  предложение, новое строчное слово делает акроним «криком».
- **Снимай настоящий вывод браузера.** Подними маленький стенд, прогони пример через Playwright
  и вставь то, что реально напечаталось. Длинные имена и абсолютные пути в выводе сокращай, но
  формат не переписывай: он проверяем.

## Артефакты детектора, которые меняют то, КАК надо писать

Полный список — `content/templates/README.md` §4 и `audit/LANGUAGE_PASS_BRIEF.md` §4. Самое
важное:

- **Начинай предложение со слова с заглавной буквы.** `SENT_SPLIT_RE` принимает после точки
  только кавычку, скобку, звёздочку, заглавную букву или цифру. `…верно. \`navigator\` даёт…`
  мерится как одно длинное предложение. Пиши «Объект `navigator` даёт…».
- **Не заканчивай предложение ссылкой или закрывающей кавычкой перед точкой** — предложение
  сольётся со следующим.
- **Пустая строка между жирной меткой и списком под ней обязательна.** Без неё `blocks_of`
  считает метку со всем списком одним абзацем прозы, и это же ломает рендеринг: `breaks: false`
  не поставит метку на свою строку.
- **Первое упоминание аббревиатуры — без бэктиков.** `to_prose` вырезает инлайн-код целиком, и
  глосса теряет свой токен. В этой зоне это касается `DOM`, `CORS`, `CSP`, `MIME`, `UI`.
- **Скобка глоссы должна стоять непосредственно после токена.** `CSP policy (content security
  policy)` флаг НЕ снимает — только `CSP (content security policy) policy`.
- **Какие имена детектор ловит, а какие нет — проверено запуском, не угадано.** Аббревиатуры
  из заглавных ловятся все: `DOM`, `CORS`, `CSP`, `MIME`, `UI`, `OPFS`, `IDB`, `XHR`, `UA`, `SW`,
  `GPU`, `WASM`, а также `a11y` и `i18n`. Из смешанных имён ловится только короткая форма вида
  `WebKit` (заглавная, одна-две строчные, снова заглавная). А `IndexedDB`, `WebAssembly`,
  `DevTools`, `MutationObserver`, `BroadcastChannel`, `SharedWorker`, `ReadableStream` детектор
  пропускает — глосса им не нужна ради метрики, но нужна ради читателя (§2.6). Свой сомнительный
  токен проверяй так:

  ```bash
  python3 - <<'PY'
  import sys; sys.path.insert(0, 'scripts/audit')
  import readability_flags as rf
  s = "Тут упомянут OPFS и дальше обычный текст."
  print([a['token'] for a in rf.find_abbreviations(rf.to_prose(s), 'ru')])
  PY
  ```
- **Ноль в счётчике ничего не доказывает.** `initials_expansion` засчитывает любые три подряд
  идущих слова, чьи начальные буквы складываются в токен; `parenthetical-before` сопоставляет
  только `(ТОКЕН)` и не смотрит, расшифровывают ли его слова перед скобкой. Читай глоссу глазами.
- **Строка таблицы мерится как одно предложение.** `split_sentences` не режет на `|`, поэтому
  длинная строка таблицы даёт флаг длинного предложения. Сокращай ячейки.
- **Шаблоны местами расходятся с корпусом.** **Верь типу в `src/types/` и корпусу, а не
  шаблону**, и сообщи о расхождении.
