## Устройство записи, и оно не такое, как в шаблоне

```
id, topicId, difficulty ('easy' | 'medium' | 'hard'), tags   — НЕ ТРОГАТЬ
title               { en, ru }   — рендерится ОБЫЧНЫМ ТЕКСТОМ
description         { en, ru }   — markdown
solutionExplanation { en, ru }   — markdown
starterCode          "строка"    — ОДНА на обе локали, НЕ ТРОГАТЬ
solution             "строка"    — ОДНА на обе локали, НЕ ТРОГАТЬ
```

`starterCode` и `solution` — **простые строки, а не пары локалей** (проверено по всем 243
записям). Шаблон `TASKS.md` описывает их как `{en,ru}` — шаблон здесь неверен, содержимое
файлов первично. Расхождение кода между локалями поэтому невозможно, и проверять его не надо.
Оба поля подсвечиваются жёстко как `typescript` (`src/app/tasks/[topicId]/[taskId]/page.tsx:51`),
даже в задачах про CSS и HTML.

**Код не правь вообще** — ни строку, ни комментарий. Дефект кода докладывай. Это правило
процесса: код общий на две локали, а на одном файле работают несколько агентов.

## Профиль дефекта в этой рубрике

Замер после механической правки: 3478 флагов. По полям: `solutionExplanation` **77%**,
`description` **22%**, `title` 0.7%. По категориям: длинные предложения 2158, длинные абзацы 764,
аббревиатуры 413, капс 143.

`solutionExplanation` написан по жёсткому шаблону:

```
**Подход:** <одно длинное предложение, нанизывающее механику, оговорки и вывод>

**Временная сложность:** …
**Пространственная сложность:** …

**Типичные ошибки:**
- …
```

Лечится так (§4.1, §4.2, §3.2):

- **Лид — одно предложение, отвечающее «почему решение такое».** Оговорки после него.
- **Механика — списком, если пунктов три и больше.** Не цепочкой через точку с запятой.
- **Крайние случаи — отдельным блоком**, если они есть в тексте.
- **Закрывающий блок («Типичные ошибки» / «Частая ловушка» / «Common mistakes») — самая
  короткая проза объяснения, а не самая длинная** (§4.3).

**Маркеры блоков не переименовывай.** В рубрике в ходу и «Типичные ошибки», и «Частая ловушка»;
переименование вне зоны работы. Слоты «Временная сложность» / «Пространственная сложность»
оставляй как есть даже там, где задача не алгоритмическая — это факт, а не язык.

## Потерянные фенсы: 280 сиротских языковых строк

Массовый дефект рендеринга. Открывающий и закрывающий ``` удалены, а языковой тег остался
отдельной строкой:

```
**Сигнатура функции:**

typescript
function loadConfig(filePath: string): Record<string, any>
```

Читатель видит это прозой. **Восстанавливай фенс** — оборачивай тело в ``` с тем самым языком,
который остался сиротской строкой. По файлам: `nodejs` 62, `typescript` 62, `testing` 46,
`css-html` 30, `react` 32, `algorithms` 24, `graphql` 24, `javascript` 0.

Замерено: по флагам это даёт почти ноль (−24 на всю рубрику), а в `css-html` даже **добавило**
две аббревиатуры и убрало два капса — тот самый артефакт «конвертация меняет обе стороны»
(`LANGUAGE_PASS_BRIEF` §4). Чини это ради читателя, а не ради счётчика, и **меряй все четыре
категории после каждой такой правки**.

## Аббревиатуры: часть находок ложная, и причина — тот же потерянный фенс

Реальные, требуют глоссы внутри задачи: `DFS`, `BFS`, `LRU`, `ASCII`, `IEEE`, `ARIA`, `IP`,
`SQL`, `MIME`, `CDN`, `TTL`, `DOM`, `SSR`, `CI`, `GC`.

Ложные — это код, попавший в прозу из-за потерянного фенса: `JSX.Element`, `MyPick`, `MyOmit`,
`NYC`, `HOST=localhost`, `PORT=3000`, `MQ==`. Лечится фенсом, **не глоссой**. Глосса на
идентификатор — бессмыслица.

Разрешены без расшифровки ровно девять токенов: `HTML CSS API JS TS URL HTTP JSON id`. Всё
остальное — при первом употреблении **внутри задачи**: карточку читают отдельно от всего.
Первое упоминание пиши **без бэктиков** — `to_prose` вырезает инлайн-код целиком, и глосса
теряет свой токен.

**Ноль в счётчике ничего не доказывает.** `initials_expansion` засчитывает любые три подряд
идущих слова, чьи начальные буквы складываются в токен; `gloss-dash` принимает тире и двоеточие;
`parenthetical-before` сопоставляет только `(ТОКЕН)` и не смотрит, расшифровывают ли его слова
перед скобкой. Читай глоссу глазами.

### Форма названия задачи: согласованность внутри файла, не внутри рубрики

24 из 29). Всего по рубрике 174 номинатива против 36 императивов.

Шаблон `TASKS.md` требует императив, и в этой части **шаблон расходится с содержимым**.

  пунктов глаголами, часть отглагольными существительными). Чини это.
- **Паритет материала** (§8.3): ни одна локаль не несёт факта, которого нет в другой. Факт
  верный — добавь во вторую, а не удаляй из первой. **По этой рубрике паритет замерен и он

  **не ищи его, а следи, чтобы не создать сам.**
- Обращение «вы» везде.
- Следов авторской работы быть не может (§8.4): «wait, actually», «let me recalculate».

## Процесс, и он не обсуждается

- **Не коммить.** Коммит — работа оркестратора.
- **Не пользуйся `Edit` и `Write`.** Вкладки-диффы съедают память IDE и уже останавливали
  агентов. Правь только питон-скриптами через `Bash`.
- **Скрипт с кириллицей в теле — через heredoc либо с `# -*- coding: utf-8 -*-`** в первой
  строке. `python3 файл.py` падает с `SyntaxError: Non-UTF-8 code` на тех же байтах, которые
  нормально компилируются через `compile()`.
- **Каждая замена под `assert n == 1`**, скрипт идемпотентный (`if n == 0 and new in text:
  continue`), имя в `/tmp` — со своего префикса: `/tmp` общий, его один раз перезаписали на
  полпути.
- **Пиши понумерованными батчами и на диск по ходу**: `<префикс>_part1.json`, `part2`, … За
  проект шесть обрывов на лимите сессии, уцелело ровно записанное.
- **Не запускай `readability_flags.py` с аргументом пути** — перезапишет закоммиченные
  `audit/readability_flags.json` и `audit/readability-flags.md`. Мерь импортом модуля.
- **Не трогай `scripts/ascii-diagrams/diagram_gen.py`.**

## Как сдавать

Если в твоём промпте сказано «правь файл напрямую» — правь. Если сказано «патч» — на одном файле
работают несколько агентов, и прямая правка потеряет чужую работу. Тогда пиши патч:

```json
{
  "nodejs-t-1": {
    "title":               { "en": "…", "ru": "…" },
    "description":         { "en": "…", "ru": "…" },
    "solutionExplanation": { "en": "…", "ru": "…" }
  }
}
```

Поле включай только если менял; обе локали в каждом включённом поле обязательны.
`json.dumps(patch, ensure_ascii=False, indent=2)`. Сливает оркестратор:
`python3 scripts/audit/merge_patch.py content/tasks/<файл>.json <патч1> <патч2>`.

## Проверка своей работы

```python
import sys; sys.path.insert(0, 'scripts/audit')
import readability_flags as rf
t = patch['nodejs-t-1']['solutionExplanation']['ru']
pr = rf.to_prose(t)
print(len(rf.find_abbreviations(pr, 'ru')), len(rf.find_long_sentences(t, 'ru')),
      len(rf.find_long_paragraphs(rf.blocks_of(t))), rf.count_caps_emphasis(pr))
```

Цель — ноль по всем четырём категориям, в обеих локалях, по каждой записи. **Меряй после каждой
пачки, а не в конце**: правка часто создаёт новый флаг (глосса удлиняет предложение, новое
строчное слово делает акроним криком).

Плюс широкие строки по своему файлу: `python3 scripts/audit/block_width.py content/tasks/<файл>.json`
— сейчас по рубрике ноль, и должен остаться нулём.

## Границы

- **Не реструктурируй то, что работает.** Правки точечные.
- **Никогда не удаляй чужие строки.** В общие файлы — только добавление.
- **Факты не правь, а докладывай.** Исключение — уровень безопасности: чини, но со ссылкой на
  первоисточник и явным докладом. **Не выдумывай расшифровку, которой не существует**: если
  официальной расшифровки нет, глоссируй проверяемым фактом.
- **Проверь, что `solution` решает именно то, что просит `description`**, и не противоречит его
  ограничениям. Расхождение — в доклад, код не трогай.
- **Что нашёл сверх задачи — запиши в отчёт.** Не чини молча.
