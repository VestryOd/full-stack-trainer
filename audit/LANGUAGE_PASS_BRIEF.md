# Бриф языкового прохода

Общий контракт для всех агентов волны. Читается один раз, дальше — только
зонный промпт.

## 1. Что считается сделанным

Зона закрыта, когда её файлы измеряют **ноль** флагов:

```bash
python3 - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, 'scripts/audit')
import readability_flags as rf
for p in sorted(Path('content/topics/<TOPIC>/en').glob('*.md')):
    t = p.read_text(encoding='utf-8'); prose = rf.to_prose(t)
    print(p.name,
          len(rf.find_abbreviations(prose, 'en')),
          len(rf.find_long_sentences(t, 'en')),
          len(rf.find_long_paragraphs(rf.blocks_of(t))),
          rf.count_caps_emphasis(prose))
PY
```

И ноль широких строк:

```bash
python3 scripts/audit/block_width.py content/topics/<TOPIC> --quiet
```

Бюджеты из `content/STYLE.md`: 68 колонок для `txt`/`text`/без тега, 92 для
кода. Предложение: 25 слов EN, 28 RU. Абзац — примерно 420 символов.

**Меряй после каждой пачки правок, а не в конце.** Правка часто создаёт новый
флаг: расшифровка удлиняет предложение, а новое слово может сделать акроним
«криком» (см. §4).

## 2. Пиши на диск по ходу

Не накапливай правки в памяти, чтобы «отдать всё сразу». Сессия может
кончиться, и тогда работа пропадёт целиком — это уже случалось. Сделал файл —
записал файл.

## 3. Правь скриптом, не руками

Для JSON и для повторяющихся правок пиши питон-скрипт в `/tmp`, где каждая
замена проверяется на единственность:

```python
n = text.count(old)
assert n == 1, f'{rel}: {n} matches for «{old[:60]}»'
```

Так дрейф исходника падает громко, а не молча ничего не делает. Скрипт делай
идемпотентным (`if n == 0 and new in text: continue`), иначе после обрыва его
нельзя перезапустить.

**Имя файла в `/tmp` начинай со своего диапазона.** Волна работает
одновременно, `/tmp` общий, и `/tmp/measure.py` уже один раз перезаписали на
полпути — агент получил чужие числа и не сразу это понял. Пиши
`/tmp/next_0105_measure.py`, а не `/tmp/measure.py`.

## 4. Известные артефакты детектора

Не борись с ними в тексте — узнавай их:

- **Предложение, кончающееся URL, сливается со следующим.** `URL_RE` съедает
  точку вместе с адресом. Не заканчивай предложение на ссылку.
- **Предложение, начинающееся со строчного inline-кода, сливается с
  предыдущим.** `` `no-store` означает…`` не считается отдельным предложением.
  Начинай следующее предложение со слова.
- **Проверяется только первое вхождение аббревиатуры.** Если рядом с ней была
  скобка и ты её переписал, аббревиатура может остаться без глоссы. И наоборот:
  глосса в четвёртом абзаце не считается.
- **Строчная половина составного слова делает акроним «криком».** `text/csv`
  так делал с `CSV`, `Node.js` — с `JS`. Это уже починено в детекторе, но если
  ты добавишь в текст обычное слово `rest`, весь `REST` в файле станет криком.
- **`---` и строка `**Вопрос?**` считаются абзацами прозы.** В банках у границы
  записи два фантомных абзаца, поэтому запаса до лимита в четыре абзаца нет.
- **Метрика проверяет форму глоссы, а не её содержание.** Голая `(TDZ)` в любом
  месте текста удовлетворяет ветку `parenthetical-before`, потому что она
  сопоставляет только `(ТОКЕН)` и не смотрит, расшифровывают ли аббревиатуру
  слова перед скобкой. Так `Kubernetes (EKS)`, `configuration file (YAML)` и
  `HTTP/3 (QUIC)` проходят как расшифрованные. Ужесточать эту ветку нельзя:
  проверка по начальным буквам ловит только латинские расшифровки, а русская
  «сетями доставки контента (CDN)» — законная глосса, которая её не пройдёт (я
  измерил: 140 срабатываний по сайту, реальных дефектов около трети). Поэтому
  **читай глоссу глазами**, а не доверяй нулю в счётчике.

## 5. Форма глоссы

Надёжнее всего работает `АКРОНИМ (расшифровка)` — любая скобка от 3 до 80
символов сразу после токена. Работают также `АКРОНИМ — расшифровка` и
естественная фраза, чьи начальные буквы складываются в акроним («content
delivery network» для CDN).

Где акроним ничего не даёт, **убери его**, а не расшифровывай. «AWS SDK» → «комплект
разработки Amazon Web Services». «LLM streaming» → «стриминг от языковой
модели». «infinite scroll UI» → «бесконечный скролл».

## 6. Что рендерится как markdown, а что нет

| Поле | Рендер |
|---|---|
| статьи `.md` | markdown + shiki |
| `question` в квизе | markdown |
| `explanation` в квизе | markdown |
| `answer` в банке | markdown |
| **`options` в квизе** | **обычный текст** |

В `options` бэктики и `**` печатаются буквально. Убирай их.

Блок заголовков или кода внутри `question`/`answer` оборачивай в fence
(```` ```http ````, ```` ```js ````, ```` ```txt ````) — тогда он и читается как
код, и уходит из прозы, где детектор ищет аббревиатуры.

## 7. Ссылки

`[Название]` без адреса markdown печатает буквально скобками. Внутритопиковые
ссылки пиши как `[Название](./04-file.md)` — рендерер переписывает их в
`/theory/<topic>/04-file`.

## 8. Границы

- **Не реструктурируй то, что работает.** Если аудит хвалит структуру зоны —
  сохраняй её. Правки минимальные и точечные.
- **Никогда не удаляй чужие строки.** Один агент однажды снёс 2623 строки из
  `scripts/ascii-diagrams/diagram_gen.py`. В общие файлы — только добавление.
- **Оба локаля.** Правка в одном без другого создаёт расхождение, а именно
  расхождения аудит и находит.
- **Код должен работать.** Если правишь пример — прогоняй его.
- **Заявка аудита — это заявка, а не приговор.** Три из четырнадцати находок
  первой волны оказались ложными. Проверь перед правкой, и если находка неверна
  — скажи об этом, а не правь под неё.
- **Что нашёл, но не входит в задачу — запиши в отчёт.** Не чини молча.
