# Бриф языкового прохода

Общий контракт для всех агентов волны. Читается один раз, дальше — только
зонный промпт.

## 1. Что считается сделанным

Зона закрыта, когда её файлы измеряют **ноль** флагов:

```bash
python3 - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, 'scripts/audit')
import readability_flags as rf
for p in sorted(Path('content/topics/<TOPIC>/en').glob('*.md')):
    t = p.read_text(encoding='utf-8'); prose = rf.to_prose(t)
    print(p.name,
          len(rf.find_abbreviations(prose, 'en')),
          len(rf.find_long_sentences(t, 'en')),
          len(rf.find_long_paragraphs(rf.blocks_of(t))),
          rf.count_caps_emphasis(prose))
PY
```

И ноль широких строк:

```bash
python3 scripts/audit/block_width.py content/topics/<TOPIC> --quiet
```

Бюджеты из `content/STYLE.md`: 68 колонок для `txt`/`text`/без тега, 92 для
кода. Предложение: 25 слов EN, 28 RU. Абзац — примерно 420 символов.

**Меряй после каждой пачки правок, а не в конце.** Правка часто создаёт новый
флаг: расшифровка удлиняет предложение, а новое слово может сделать акроним
«криком» (см. §4).

## 2. Пиши на диск по ходу

Не накапливай правки в памяти, чтобы «отдать всё сразу». Сессия может
кончиться, и тогда работа пропадёт целиком — это уже случалось. Сделал файл —
записал файл.

## 3. Правь скриптом, не руками

Для JSON и для повторяющихся правок пиши питон-скрипт в `/tmp`, где каждая
замена проверяется на единственность:

```python
n = text.count(old)
assert n == 1, f'{rel}: {n} matches for «{old[:60]}»'
```

Так дрейф исходника падает громко, а не молча ничего не делает. Скрипт делай
идемпотентным (`if n == 0 and new in text: continue`), иначе после обрыва его
нельзя перезапустить.

**Имя файла в `/tmp` начинай со своего диапазона.** Волна работает
одновременно, `/tmp` общий, и `/tmp/measure.py` уже один раз перезаписали на
полпути — агент получил чужие числа и не сразу это понял. Пиши
`/tmp/next_0105_measure.py`, а не `/tmp/measure.py`.

## 4. Известные артефакты детектора

Не борись с ними в тексте — узнавай их:

- **Предложение, кончающееся URL, сливается со следующим.** `URL_RE` съедает
  точку вместе с адресом. Не заканчивай предложение на ссылку.
- **Предложение, начинающееся с inline-кода ЛЮБОГО регистра, сливается с
  предыдущим.** Здесь раньше стояло «строчного» — это неверно и измерено в волне 22:
  `SENT_SPLIT_RE` требует после точки один из `[«"(\[*A-ZА-ЯЁ0-9]`, а `PROTECT_RE`
  прячет инлайн-код в `\x00N\x00`, которого в этом классе нет. Поэтому
  `` `Observable` `` глушит разрез так же, как `` `observable` ``:
  ```
  1 <- It ends here. `Observable` starts a new one.
  1 <- It ends here. `observable` starts a new one.
  2 <- It ends here. Observable starts a new one.
  ```
  Начинай следующее предложение со слова. **Но не спиши на артефакт всё:** в
  `rxjs/08` агент назвал его «доминирующей причиной» 45 флагов, а замер дал 7
  склеек, распадающихся на 59 предложений, из которых 40 всё равно сверх лимита.
- **Проверяется только первое вхождение аббревиатуры.** Если рядом с ней была
  скобка и ты её переписал, аббревиатура может остаться без глоссы. И наоборот:
  глосса в четвёртом абзаце не считается.
- **Строчная половина составного слова делает акроним «криком».** `text/csv`
  так делал с `CSV`, `Node.js` — с `JS`. Это уже починено в детекторе, но если
  ты добавишь в текст обычное слово `rest`, весь `REST` в файле станет криком.
- **`---` и строка `**Вопрос?**` считаются абзацами прозы.** В банках у границы
  записи два фантомных абзаца, поэтому запаса до лимита в четыре абзаца нет.
- **Жирная метка над списком без пустой строки — это один абзац прозы.**
  `blocks_of` видит `**Дефолтный конвейер** (…)` и весь список под ней как
  единый `para`, и в одной записи так намерилось 26 строк. Поставь пустую
  строку между меткой и списком — список станет блоком типа `list` и перестанет
  мериться как проза. Это самый механический способ снять флаги «стена текста».

  **Сколько он даёт — функция длины списка, а не свойство приёма.** Замерен
  четырежды с разным итогом (`oop-patterns` много, банк `architecture` ноль,
  глоссарий `cicd-devops` −21/−22 абзаца, файл 09 там же −2). Пустая строка
  **необходима всегда**, но **платит только когда метка вместе со своим списком
  переваливает за 420 символов** — короткие пары остаются под лимитом и слитыми.
  Не закладывай приём в оценку зоны, не померив его на одной пробной пачке.

  И он чинит не только метрику: `ArticleRenderer.tsx:69` ставит `breaks: false`,
  поэтому `**Термин**` с текстом на следующей строке рендерится **одним слитным
  абзацем**. Без пустой строки метка не стоит на своей строке и на сайте.
- **`to_prose` вырезает инлайн-код целиком, и глосса на код-токене теряет свой
  токен.** `` `ENOENT` (error, no entry) `` превращается в прозе в сироту
  «(error, no entry)», а первым вхождением становится голый `ENOENT` в соседнем
  поле. Стайлгайд это и запрещает («глосса не внутри кода»), но по счётчику
  дефект выглядит как законный остаток §2.2. Первое упоминание пиши без
  бэктиков, бэктики оставляй последующим.
- **Конвертация фенса в markdown СОЗДАЁТ флаги, а не только снимает широкие строки.**
  Найдено волной 22. У box-таблицы содержимое лежит внутри фенса, а `to_prose`
  вырезает фенсы целиком; markdown-таблица — это **проза**. Всё, что уезжает из
  фенса в таблицу, начинает считаться, поэтому приём «box-таблица → markdown»
  умеет добавить флаг любой из четырёх категорий.

  Измерено: в главе 00 курса `angular` строка `| core | react + react-dom | |`
  уехала в прозу, и строчный `react-dom` заглушил акроним `DOM` — **4 ложных
  капс-флага там, где был ноль** (`is_caps_emphasis` исключает из границ слова `.`
  и `/`, но не дефис). Чинится бэктиками вокруг имени пакета.

  **Меряй все четыре категории после каждой конвертации.** Скан зоны до правок
  ничего не гарантирует: риск создаёт сама правка.

  Побочно это же поднимает число слов в `COVERAGE.md` без нового контента — в
  волне 22 из +10 341 слова курса 6 317 оказались текстом таблиц, ставшим видимым.
- **Капс и аббревиатуры длиннее шести символов не проверяются вообще.**
  `ABBR_UPPER_RE = ([A-Z][A-Z0-9]{1,5})`, `ABBR_CYRILLIC_RE = ([А-ЯЁ]{2,6})`.
  Измерено: `ДОЛЖНЫ` и `ВНУТРИ` (6 букв) ловятся, `КРАТКАЯ` и `НИКОГДА` (7) —
  нет. Практический след по сайту невелик, потому что большинство длинных
  капс-токенов это законные идентификаторы (`SIGTERM`, `EXPLAIN`,
  `SERIALIZABLE`, `ENTRYPOINT`), но акронимы `SQLSTATE` и `HATEOAS` метрика
  не проверит никогда — все их вхождения на сайте стоят без расшифровки.
- **Ветка `initials_expansion` засчитывает ложную глоссу.** Любые три подряд
  идущих слова, чьи начальные буквы складываются в токен, считаются
  расшифровкой. Так проходили `AMD (define([...]))`, `UMD, a wrapper trying
  to…`, `NX (executors…)`, `CDN`, `KB`. Вместе с фальшивой скобочной глоссой
  и потерей токена внутри инлайн-кода это **три разных способа получить
  ложный ноль** — читай глоссу глазами.
- **Токен с подчёркиванием не проверяется, а его сосед без подчёркивания —
  проверяется.** В `postgresql-q-8` `RANK` флагуется как нераскрытая
  аббревиатура, а `ROW_NUMBER` и `DENSE_RANK` в том же предложении — нет.
  Это имена функций SQL; глосса к ключевому слову была бы бессмыслицей, а `()`
  счётчик не снимает. Узнавай и оставляй.
- **Апострофные формы (`pod'ы`, `executor'ов`) не видит ни одна метрика**, хотя
  §7.2 стайлгайда их прямо запрещает. В `cicd-devops` их пережило проход 15 штук
  при трёх агентах, чистивших кальку. Лови грепом в конце зоны:
  `grep -rn "[A-Za-z]\+'[а-яё]\+" content/topics/<зона>/ru/`. Сужая замену,
  помни, что `awk length()` считает байты, а бюджет ширины — колонки.
- **Предложение, кончающееся закрывающей кавычкой перед точкой, не
  отделяется.** `…more".` и `…корня?»` склеиваются со следующим, и два
  коротких предложения мерятся как одно длинное.
- **`BigInt` ловится как ложный акроним** паттерном смешанного регистра.
  Глоссу проще поставить, чем спорить с детектором.
- **Метрика проверяет форму глоссы, а не её содержание.** Голая `(TDZ)` в любом
  месте текста удовлетворяет ветку `parenthetical-before`, потому что она
  сопоставляет только `(ТОКЕН)` и не смотрит, расшифровывают ли аббревиатуру
  слова перед скобкой. Так `Kubernetes (EKS)`, `configuration file (YAML)` и
  `HTTP/3 (QUIC)` проходят как расшифрованные. Ужесточать эту ветку нельзя:
  проверка по начальным буквам ловит только латинские расшифровки, а русская
  «сетями доставки контента (CDN)» — законная глосса, которая её не пройдёт (я
  измерил: 140 срабатываний по сайту, реальных дефектов около трети). Поэтому
  **читай глоссу глазами**, а не доверяй нулю в счётчике.

## 5. Форма глоссы

Надёжнее всего работает `АКРОНИМ (расшифровка)` — любая скобка от 3 до 80
символов сразу после токена. Работают также `АКРОНИМ — расшифровка` и
естественная фраза, чьи начальные буквы складываются в акроним («content
delivery network» для CDN).

Где акроним ничего не даёт, **убери его**, а не расшифровывай. «AWS SDK» → «комплект
разработки Amazon Web Services». «LLM streaming» → «стриминг от языковой
модели». «infinite scroll UI» → «бесконечный скролл».

## 6. Что рендерится как markdown, а что нет

| Поле | Рендер |
|---|---|
| статьи `.md` | markdown + shiki |
| `question` в квизе | markdown |
| `explanation` в квизе | markdown |
| `answer` в банке | markdown |
| **`options` в квизе** | **обычный текст** |
| **`question` в банке** | **обычный текст** |

В `options` квиза и в `question` банка бэктики и `**` печатаются буквально —
`QuizCard.tsx` кладёт вариант прямо в кнопку, а `QuestionCard.tsx` берёт
`question.question[locale]` как текст, тогда как для ответа готовит
`answerHtml`. По сайту так печатается 352 текста вопросов в банках, больше
всего в `python` (146) и `typescript` (96) — это записанный долг.

Блок заголовков или кода внутри `question`/`answer` оборачивай в fence
(```` ```http ````, ```` ```js ````, ```` ```txt ````) — тогда он и читается как
код, и уходит из прозы, где детектор ищет аббревиатуры.

## 7. Ссылки

`[Название]` без адреса markdown печатает буквально скобками. Внутритопиковые
ссылки пиши как `[Название](./04-file.md)` — рендерер переписывает их в
`/theory/<topic>/04-file`.

## 8. Границы

- **Не реструктурируй то, что работает.** Если аудит хвалит структуру зоны —
  сохраняй её. Правки минимальные и точечные.
- **Никогда не удаляй чужие строки.** Один агент однажды снёс 2623 строки из
  `scripts/ascii-diagrams/diagram_gen.py`. В общие файлы — только добавление.
- **Оба локаля.** Правка в одном без другого создаёт расхождение, а именно
  расхождения аудит и находит.
- **Код должен работать.** Если правишь пример — прогоняй его.
- **Заявка аудита — это заявка, а не приговор.** Три из четырнадцати находок
  первой волны оказались ложными. Проверь перед правкой, и если находка неверна
  — скажи об этом, а не правь под неё.
- **Что нашёл, но не входит в задачу — запиши в отчёт.** Не чини молча.
