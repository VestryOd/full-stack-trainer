# Coverage report — фаза 1

Источник данных: `audit/inventory.json` (сгенерирован `scripts/audit/inventory.py`), плюс точечные
проверки grep'ом по `content/`. Ничего в `content/` не изменялось.

Обозначения статуса:

- **полное** — есть теория (статьи), закрепление (вопросы/quiz/задачи) и тема раскрыта на уровне,
  который спрашивают на интервью middle/senior;
- **частично** — тема присутствует, но с явной дырой: либо нет теории, либо нет закрепления,
  либо раскрыта только часть подтем;
- **пробел** — темы фактически нет (только упоминания в чужих статьях).

Столбцы «статьи / вопросы / quiz / задачи» — фактические числа из инвентаря. Прочерк = ноль.

### 3.3 Перекрёстные ссылки не работают как ссылки

576 упоминаний вида `(см. [Message Queues])` — это обычный текст в markdown, не ссылки. Читатель
видит квадратные скобки и не может никуда перейти. Ещё 34 таких упоминания не находят статью даже
по нечёткому совпадению — все в `cicd-devops/ru/08-glossary-and-acronyms.md`, потому что глоссарий
ссылается на русские названия («Основы CI/CD»), а H1 у этих русских статей остались английскими
(«CI/CD Fundamentals»).

## 4. Дефекты содержания, найденные попутно

**Критично: `content/questions/postgresql.json` — это копия банка HTTP/REST.**
Все 25 записей имеют `topicId: "http-rest"` и `id` вида `http-rest-q-N`; 15 вопросов дословно
совпадают с `http-rest.json`. `src/lib/questions.ts` читает банк по имени файла, поэтому на
странице вопросов PostgreSQL пользователю показываются вопросы про PUT/PATCH, статус 204 и CORS.
Следствие: **у PostgreSQL фактически нет банка вопросов**, а у HTTP/REST их вдвое больше, чем
кажется.

**Уточнение из фазы 2 — какой файл сохранять.** Интуитивное решение «удалить `postgresql.json`»
неверно: аудит показал, что это **более поздняя и лучшая редакция** банка HTTP/REST. Вопросы
q-1…q-15 в двух файлах идентичны байт в байт, а все десять senior-вопросов q-16…q-25 переписаны
заново: ответы длиннее в 3-4 раза (80-140 слов RU → 366-486), добавлены ASCII-диаграммы и сниппеты
nginx/JSON, используется новый маркер ловушки и обращение «ты». Главное — в `http-rest.json`
senior-уровень покрывает всего пять различных тем на десять слотов (q16≈q21 про мультиплексирование
HTTP/2, q18≈q23 про WebSockets/SSE, q19≈q24 про идемпотентность, q20≈q25 про трейсинг), а
переписанная версия даёт десять разных тем (добавлены TLS-resumption, HATEOAS/Richardson, RFC 7807,
circuit breaker, HMAC для вебхуков).

Значит, правка такая: **содержимое `postgresql.json` переносится в `http-rest.json`** (и получает
корректные `id`), после чего для PostgreSQL пишется настоящий банк с нуля. Заодно в выжившем файле
надо схлопнуть дубли среднего уровня — q6≈q11, q7≈q14, q8≈q12, q9≈q13, q10≈q15.

**Два поколения шаблона ответа.** Первая редакция этого отчёта утверждала, что в 155 вопросах нет
маркера «Частая ловушка / Common pitfall». Это **неверно** — проверка фазы 2 показала, что маркер
есть во всех 1317 вопросах, но в двух формулировках: новой («Частая ловушка / Common pitfall») и
старой («Типичная ошибка на интервью / Common interview trap»). Скрипт искал только первую.
`scripts/audit/inventory.py` исправлен, число пропусков теперь ноль.

Само расслоение на два поколения при этом реально и видно по другим признакам. Старый шаблон
опознаётся по формулировке маркера и сопутствует более слабому тексту: аудитор банка `nodejs`
показал, что ровно те 23 ответа со старым маркером (q-21…28, q-36…41, q-51…58) не имеют
итогового абзаца после кода и написаны калькированным русским; в банке `react`, наоборот, старый
маркер стоит у senior-уровня (q-51…68), и это **самая читаемая** треть банка. То есть маркер
указывает на поколение, а не на качество — качество надо смотреть глазами.

**Три банка заметно короче остальных по прозе:** `graphql` (49 слов на ответ), `http-rest` (57),
`prisma` (73) против 186 в среднем. Для `prisma` аудитор уточнил: с кодом ответы выходят на
135 слов, то есть банк не столько короткий, сколько код-ориентированный — но 15 из 40 его ответов
всё равно уступают по глубине статьям того же топика, которые они дублируют.

**79 русских статей с английским H1.** Полностью затронуты `mongodb-mongoose` (8 из 9) и
`cicd-devops` (7 из 9), плюс `nestjs`, `nextjs`, `graphql`, `aws`. Часть случаев спорна
(`API Gateway`, `GitHub Actions` — имена собственные), но большинство — просто непереведённые
заголовки (`Indexes and Query Performance`, `Document Model and Use Cases`).

**Маркер `<!-- verified: -->` есть только на 122 файлах из 652** (все 100 файлов курсов — без
него). Если этот маркер означает факт-чекинг, то 81% контента не верифицирован.

## 6. Что важно не потерять при исправлении

- Покрытие **тем** в целом сильное: 30 узлов карты закрыты полностью, и по объёму (487k слов RU
  в теории) сайт уже плотнее большинства бесплатных ресурсов. Пробелы — не «мало контента», а
  «контент не там, где его ждут»: теория без вопросов, вопросы без теории, курс без входа из топика.
- Три из четырёх крупнейших пробелов (SQL, формы, серверное состояние) — прикладные, а не
  теоретические. Их закрытие не требует новой глубины, только новых глав в существующих топиках.
- Один баг (`postgresql.json`) стоит починить раньше любой генерации нового контента: он делает
  уже написанные 7 статей и 29 quiz по PostgreSQL наполовину бесполезными.
