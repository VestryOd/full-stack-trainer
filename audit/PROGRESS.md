## Как это делать (проверенный способ)

Пользователь дал постоянное разрешение сразу звать субагентов и вести 2-3 зоны параллельно.

1. Бриф для агента — `audit/readability/AGENT_BRIEF.md`. Он полный: контракт, что править, что не
   трогать, как проверять, что докладывать. В промпте агента остаётся только зона, диапазон и находки
   аудита по этой зоне из `audit/readability/<зона>.json`.
2. **Несколько агентов на одном файле обязаны писать patch-файлы, а не править файл.** Каждый делает
   read → mutate → write, поэтому прямая правка одного файла двумя агентами теряет работу одного из
   них. Слияние: `python3 scripts/audit/merge_patch.py <банк> <патч1> <патч2>` — он же проверяет, что
   обе локали на месте.
3. Один агент на свой файл (или набор файлов) может править напрямую — гонки нет.
4. Замер до и после: `python3 scripts/audit/readability_flags.py <путь> --json-out /tmp/x.json
   --md-out ""`. **Скрипт перезаписывает `audit/readability_flags.json`** — это закоммиченная базовая
   линия, после прогона восстанавливать: `git checkout -- audit/readability_flags.json`.
5. После слияния — `npm run build`, проверка смешанного алфавита и следов генерации, `git diff --stat`.

## Известные особенности инструментов

- `split_sentences` не режет предложение, если следующее начинается со строчного inline-кода
  (`…верно. \`useState\` особенный…` считается одним предложением). Писать «Хук `useState`…».
- `I/O` считается двумя словами, а предложение, кончающееся на `I/O.`, не режется: `O.` выглядит как
  инициал.
- Скобочная глосса аббревиатуры добавляет 3-5 слов и может вытолкнуть предложение за лимит. Тогда
  глоссу выносить в отдельное короткое предложение.
- Метрика «стены теории» конфликтует с разбиением длинных предложений. Разрешать добавлением списка,
  таблицы или код-блока, который показывает уже сказанное, а не слиянием абзацев назад.

## Проход по корректности — закрыт (коммиты `c307281`, `ec41565`, `c1ec93f`)

Долг, накопленный языковыми агентами. Каждое утверждение перед правкой перепроверялось по
первоисточнику; правила прохода — в `audit/FACT_CHECK_BRIEF.md`.

Исправлено в `questions/nodejs.json`: `defaultMaxListeners` = 10 (было 16), дефолты `highWaterMark`
(64KB для байтов с Node.js 22, 16 **объектов** для object mode), `asyncLocalStorage.exit()` вместо
несуществующего `exitContext()`, `'finish'` не синхронный, `subscribe()` ничего не возвращает,
дефолтный heap выводится из доступной памяти (а не «~1.4GB независимо от лимита»), флаг
`--permission` стабилен с v22.13. Найдено попутно и хуже заявленного: q-99 учил модели прав **Deno**,
а не Node — `--allow-net=host:port` в Node не существует, флаг булев и появился только в v25.
Мёртвые зависимости: `csurf` (deprecated на npm, последний релиз 2020-01-19) → `csrf-csrf` 4.x;
`spdy` (без релизов с 2020-04-04) → нативный compatibility API и терминация HTTP/2 на прокси.
Уточнено по ChangeLog libuv: cgroup v2 — с Node.js 20.3, а не с 21.

Исправлено в `questions/react.json`: `ReactDOM.render` удалён в React 19 (не «сохраняет legacy»),
`defaultProps` удалён у функциональных компонентов (классовые сохраняют), и найденное свипом
`react-q-17` — React 19 больше не проверяет `propTypes` и не предупреждает вовсе.

Закрыто там же: `nodejs-q-53`, `q-55`, `q-58` отвечали на более узкий вопрос, чем задавали —
добавлены Node-API против node-gyp, пример на `perf_hooks`, пример на `AsyncLocalStorage`.

**Что из этого долга осталось:**

- неопределённые идентификаторы в сниппетах — свип по обоим банкам. Массовая правка не нужна:
  фрагмент вида `server.on(...)` без создания `server` — нормальная конвенция. Править только там,
  где пропуск делает пример неверным;
- 74 таблицы, добавленные react-проходом: факты в ячейках не проверялись, а таблица читается
  авторитетнее прозы.

**Решение по react-проходу:** рост банка на 25% (62.6k → 77.9k слов) оставляем — решение
пользователя от 2026-08-19. Восстановленная русская версия в 27 записях и 74 таблицы остаются.

## Исходный список долга (для истории)

Агенты по инструкции не правят факты и код, а докладывают. Накопилось около 40 пунктов; самые
серьёзные — неверные утверждения:

- `nodejs-q-59`: дефолтный heap заявлен ~1.4GB и абзацем ниже сам себе противоречит (с Node 12 дефолт
  зависит от доступной памяти);
- `nodejs-q-56`: `subscribe()` якобы возвращает AbortController-совместимый handle — не возвращает;
- `nodejs-q-99`: флаг назван `--experimental-permission`, сейчас `--permission`;
- `nodejs-q-39`: упомянут `exitContext()`, которого нет (есть `exit()`);
- `nodejs-q-45`: `'finish'` назван синхронным;
- `nodejs-q-23`: `defaultMaxListeners` равен 10, а не 16;
- `nodejs-q-21`: «16KB для object mode» — на самом деле 16 объектов;
- `react-q-55`: `ReactDOM.render` описан как сохраняющий legacy-поведение, в React 19 он удалён;
- `react-q-18`: «постепенно убирают» `defaultProps`, хотя в React 19 уже удалён.

Плюс: `nodejs-q-53`, `q-55`, `q-58` отвечают на более узкий вопрос, чем задают; неопределённые
идентификаторы в сниппетах массово в обоих банках; `csurf` (deprecated) и `spdy` (не поддерживается)
рекомендуются как решения.
