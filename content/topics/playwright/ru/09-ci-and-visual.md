# Прогон в пайплайне: что Playwright требует от машины сборки

На сервере сборки тест идёт в другом окружении: другая операционная система,
другие шрифты, другой часовой пояс и вдвое меньше ядер. Такую автоматическую
сборку и проверку обычно называют CI (continuous integration — непрерывная
интеграция). Разница между машинами предсказуема, и закрывается она настройками
проекта плюс правильной упаковкой прогона.

## Всё, что не задано в конфиге, тест берёт у машины

Тест не живёт в пустоте: часовой пояс, язык, размер окна и шрифты он получает от
системы, если вы не сказали иначе.

```txt
             Один и тот же тест на двух машинах
┌─────────────────────────┐  ┌─────────────────────────────┐
│ Ноутбук разработчика    │  │ Машина сборки               │
│                         │  │                             │
│ система: macOS          │  │ система: Linux в контейнере │
│ шрифты: системные       │  │ шрифты: те, что положили    │
│ экран: ретина, x2       │  │ экран: без экрана вовсе     │
│ пояс: Europe/Bratislava │  │ пояс: UTC                   │
│ язык: en-US             │  │ язык: C или en-US           │
│ ядер: 11                │  │ ядер: 2                     │
└─────────────────────────┘  └─────────────────────────────┘
     всё, что не задано в конфиге, приезжает из машины:
  дата, формат чисел, размер окна и даже начертание шрифта
```

Проверить это можно за один прогон. Ниже два теста, отличающиеся только тем, что
первый фиксирует окружение, а второй полагается на машину.

```ts
// tests/env.spec.ts
test.describe('окружение машины', () => {
  test.use({ timezoneId: 'Europe/Kyiv', locale: 'uk-UA',
             viewport: { width: 1280, height: 720 } });

  test('часовой пояс и локаль заданы проектом', async ({ page }) => {
    await page.goto('/tasks');
    const date = await page.evaluate(
      () => new Date('2026-09-18T21:30:00Z').toLocaleString());
    console.log(`  date: ${date}`);
  });
});
```

Один и тот же момент времени печатается по-разному.

```txt
timeZone: Europe/Kiev
locale:   uk-UA
viewport: 1280x720
date:     19.09.2026, 00:30:00

timeZone: Europe/Bratislava
locale:   en-US
viewport: 1280x720
date:     9/18/2026, 11:30:00 PM
```

Разница не только в формате: у первого теста это уже девятнадцатое сентября, а у
второго ещё восемнадцатое. Тест, который сравнивает дату на странице с
ожидаемой, будет падать по ночам, пока часовой пояс не зафиксирован. То же
касается языка: `toLocaleString` и сортировка строк зависят от локали.

```ts
// playwright.config.ts — окружение задано явно и одинаково везде
export default defineConfig({
  use: {
    timezoneId: 'Europe/Kyiv',
    locale: 'uk-UA',
    viewport: { width: 1280, height: 720 },
    colorScheme: 'light',
  },
});
```

## Контейнер убирает остаток разницы

Часовой пояс и язык задаются конфигом, а вот версия браузера, набор шрифтов и
системные библиотеки — нет. Их выравнивает готовый образ, который выпускается
под каждую версию пакета.

```yaml
# фрагмент задания сборки: образ той же версии, что и пакет
container:
  image: mcr.microsoft.com/playwright:v1.63.0-noble
```

Совпадение версий здесь обязательное, а не желательное. Образ несёт в себе
сборки браузеров, и при расхождении версий пакет либо докачает свои, либо
откажется стартовать. Если образ не используется, браузеры и системные
зависимости ставят руками.

```bash
# на чистой машине: браузеры плюс системные библиотеки к ним
npx playwright install --with-deps chromium
```

Само устройство пайплайна — шаги, кэш, права, окружения — тема соседней зоны про
непрерывную поставку и эксплуатацию, которая называется CI/CD & DevOps
(разработка и эксплуатация). Здесь
важно только то, что требует именно Playwright: контейнер или установка с
зависимостями, число воркеров по числу ядер и место для артефактов.

## Шардирование в матрице и сборка общего отчёта

Шардирование делит набор между машинами, но каждая машина получает свой кусок
отчёта. Чтобы отчёт снова стал одним, шарды пишут в промежуточный формат `blob`,
а потом объединяют.

```yaml
# фрагмент матрицы: четыре машины, каждая со своей долей набора
strategy:
  matrix:
    shard: [1, 2, 3, 4]
steps:
  - run: npx playwright test --shard=${{ matrix.shard }}/4 --reporter=blob
```

Каждый прогон кладёт свой архив в каталог `blob-report`. Эти архивы собирают в
одно место и склеивают одной командой.

```bash
npx playwright merge-reports --reporter=html ./all-blob-reports
```

Склейка — обычный прогон отчёта, а не повторный запуск тестов.

```txt
Running 4 tests using 2 workers

✓  1 [chromium] › tests/part1.spec.ts:3:5 › часть 1: список (185ms)
✓  2 [chromium] › tests/part1.spec.ts:8:5 › часть 1: страницы (54ms)
✓  3 [chromium] › tests/part2.spec.ts:3:5 › часть 2: список (76ms)
✓  4 [chromium] › tests/part2.spec.ts:8:5 › часть 2: страницы (57ms)

4 passed (1.8s)
```

## Визуальное сравнение привязано к браузеру и системе

Сравнение картинок сравнивает пиксели, а пиксели зависят от того, кто их
рисовал. Playwright об этом знает и вшивает имя браузера и системы прямо в имя
файла эталона.

```ts
test('список задач выглядит как эталон', async ({ page }) => {
  await page.goto('/tasks');
  await expect(page.getByRole('listitem')).toHaveCount(20);

  await expect(page).toHaveScreenshot('tasks.png');
});
```

На первом прогоне эталона ещё нет, и тест падает, сохранив снимок.

```txt
Error: A snapshot doesn't exist at
  tests/vis.spec.ts-snapshots/tasks-chromium-darwin.png,
  writing actual.
```

Суффикс `chromium-darwin` и есть ответ на вопрос «почему у коллеги не сходится».
Эталон, снятый на macOS в Chromium, не подходит ни другому браузеру, ни Linux в
контейнере. Отсюда практика: эталоны снимают в том же образе, в котором потом
идёт проверка.

Когда картинки расходятся, в отчёте видно, насколько именно.

```txt
Error: expect(page).toHaveScreenshot(expected) failed

  4991 pixels (ratio 0.01 of all image pixels) are different.
  Snapshot: tasks.png

Call log:
  - Expect "toHaveScreenshot(tasks.png)" with timeout 5000ms
  - taking page screenshot
    - disabled all CSS animations
    - waiting for fonts to load...
    - fonts loaded
  - 4991 pixels (ratio 0.01 of all image pixels) are different.
  - waiting 100ms before taking screenshot
  - captured a stable screenshot
```

В журнале видно и то, как инструмент борется за повторяемость сам: отключает
анимации, ждёт загрузки шрифтов и снимает картинку дважды, пока она не
перестанет меняться. Рядом с отчётом остаются три файла: ожидаемый, полученный и
их разница.

| настройка | зачем |
|---|---|
| `maxDiffPixels` | допуск в пикселях на мелкое несовпадение сглаживания |
| `maxDiffPixelRatio` | тот же допуск, но долей от площади картинки |
| `threshold` | насколько сильно должен отличаться пиксель, чтобы считаться другим |
| `mask` | закрыть заведомо изменчивые места: дату, аватар, рекламу |
| `stylePath` | подключить стили, прячущие анимации и динамику |
| `animations` | по умолчанию анимации отключены на время снимка |

## Обновление эталонов — отдельная операция

Эталоны не обновляются сами: пока вы не сказали, расхождение считается дефектом.

```bash
# перерисовать только изменившиеся эталоны
npx playwright test --update-snapshots=changed
```

Режимов четыре, и они видны в справке: `all` переписывает все эталоны, `changed`
только расходящиеся, `missing` только недостающие, `none` не пишет ничего. Без
флага работает режим `missing`, а флаг без значения означает `changed`.

Перерисовывать эталоны стоит там же, где они проверяются. Обновление на ноутбуке
с последующей проверкой в контейнере — самый частый способ получить вечно
красный тест.

## Артефакты и кэш: что выгружать и что не хранить

Артефакты нужны после прогона, поэтому их выгружают из пайплайна как файлы.
Выгружают обычно три вещи: отчёт, трассировки упавших тестов и снимки
несовпавших картинок.

```yaml
# фрагмент задания: сохранить отчёт, даже если тесты упали
- uses: actions/upload-artifact@v4
  if: always()
  with:
    name: playwright-report
    path: playwright-report/
    retention-days: 7
```

С кэшем всё наоборот. Сборки браузеров лежат в системном каталоге и занимают
сотни мегабайт: на моей машине это 557 мегабайт на три компонента. Официальная
рекомендация — браузеры не кэшировать: восстановление кэша занимает примерно
столько же, сколько скачивание, а системные зависимости кэшу вообще не
поддаются. Кэшируют то, что кэшируется дёшево: зависимости `npm`.

## Типичные ошибки

- **Снимать эталоны на ноутбуке, а проверять в контейнере.** Симптом: тест
  краснеет у всех, кроме автора эталона.
- **Держать версию образа и версию пакета вразнобой.** Симптом: прогон в
  контейнере докачивает браузеры или падает при старте.
- **Ставить столько же воркеров, сколько локально.** Симптом: на двух ядрах
  тесты начинают падать по таймауту, потому что дерутся за процессор.
- **Забыть `if: always()` при выгрузке отчёта.** Симптом: отчёт есть только у
  зелёных прогонов, то есть именно тогда, когда он не нужен.
