# Тест управляет сетью, а не надеется на неё

Обработчик `route` перехватывает запрос до того, как тот уйдёт в сеть. Тест сам
решает, ответить заготовленными данными, оборвать запрос, изменить его или
пропустить как есть. Это превращает сеть из источника случайностей в часть
условий теста.

## Обработчик стоит между страницей и сетью

Регистрация обработчика — это правило «на такие адреса отвечаю я».

```ts
// tests/tasks.spec.ts
import { test, expect } from '@playwright/test';

test('пустой список показывает подсказку', async ({ page }) => {
  await page.route('**/api/tasks*', async (route) => {
    await route.fulfill({
      json: { items: [], total: 0, page: 1, pages: 1 },
    });
  });

  await page.goto('/tasks');

  await expect(page.getByText('Нет задач')).toBeVisible();
  await expect(page.getByRole('listitem')).toHaveCount(0);
});
```

Приложение сходило за данными как обычно, но ответ пришёл из теста. Так
проверяют состояния, которые трудно получить на настоящем сервере: пустой
список, ошибку, медленный ответ, битые данные.

| метод | что делает | чем заканчивается |
|---|---|---|
| `route.fulfill()` | отвечает заготовленными данными | цепочка обрывается |
| `route.abort()` | обрывает запрос как сетевую ошибку | цепочка обрывается |
| `route.continue()` | пропускает в сеть, можно изменить запрос | остальные обработчики пропускаются |
| `route.fallback()` | передаёт запрос следующему обработчику | цепочка продолжается |

Разница между `continue()` и `fallback()` — главная тонкость этого раздела.
Первый отправляет запрос в сеть немедленно, второй передаёт его дальше по
цепочке обработчиков.

## Порядок обработчиков обратный: последний объявленный идёт первым

Обработчики выстраиваются в цепочку, и вход в неё — с конца списка регистраций.

```txt
  Путь запроса GET /api/tasks через обработчики
┌───────────────────────────────┐
│ Страница шлёт запрос          │
│ fetch внутри приложения       │
└───────────────────────────────┘
                │  перехват до выхода в сеть
                ▼
┌───────────────────────────────┐
│ page.route, объявлен вторым   │
│ его очередь первая            │
└───────────────────────────────┘
                │  обработчик вызвал fallback()
                ▼
┌───────────────────────────────┐
│ page.route, объявлен первым   │
│ его очередь вторая            │
└───────────────────────────────┘
                │  снова fallback()
                ▼
┌───────────────────────────────┐
│ context.route                 │
│ очередь после всех page.route │
└───────────────────────────────┘
                │  снова fallback() или continue()
                ▼
┌───────────────────────────────┐
│ Настоящая сеть                │
│ запрос дошёл до сервера       │
└───────────────────────────────┘
  fulfill() и abort() обрывают цепочку на месте,
continue() уходит в сеть мимо оставшихся обработчиков
```

Проверяется это одним тестом с печатью из каждого обработчика.

```ts
test('порядок обработчиков', async ({ page, context }) => {
  await context.route('**/api/tasks*', async (route) => {
    console.log('  context.route: первый зарегистрированный');
    await route.fallback();
  });
  await page.route('**/api/tasks*', async (route) => {
    console.log('  page.route #1 (зарегистрирован раньше)');
    await route.fallback();
  });
  await page.route('**/api/tasks*', async (route) => {
    console.log('  page.route #2 (зарегистрирован позже)');
    await route.fallback();
  });

  await page.goto('/tasks');
});
```

```txt
  page.route #2 (зарегистрирован позже)
  page.route #1 (зарегистрирован раньше)
  context.route: первый зарегистрированный
  ✓  1 tests/route.spec.ts:3:5 › порядок обработчиков (303ms)
```

Отсюда два правила. Общую заглушку ставят в контексте или в начале файла, а
частную — прямо в тесте, и она перекроет общую. Если частный обработчик вместо
`fallback()` вызовет `continue()`, общий не выполнится вовсе.

## Подменять стоит не всё подряд

Подмена делает тест быстрым и устойчивым, но ровно настолько же — слепым.

| что проверяет тест | где брать данные |
|---|---|
| отрисовку пустого списка, ошибки, длинного текста | заглушка в тесте |
| редкий ответ сервера: `500`, тайм-аут, битый `JSON` | заглушка в тесте |
| что фильтр шлёт правильный запрос | настоящий сервер плюс проверка запроса |
| что вход выдаёт рабочую сессию | настоящий сервер |
| сквозной сценарий до базы данных | настоящий сервер |

Правило простое: подменяют то, что мешает проверить интерфейс, и не подменяют
то, что тест как раз и должен проверить. Тест на вход с подменённым
`POST /api/login` проверяет только вёрстку формы.

Проверить сам запрос помогает `route.continue()` без изменений — обработчик
видит запрос и пропускает его.

```ts
test('фильтр уходит на сервер с нужным параметром', async ({ page }) => {
  const urls: string[] = [];
  await page.route('**/api/tasks*', async (route) => {
    urls.push(route.request().url());
    await route.continue();                 // данные настоящие
  });

  await page.goto('/tasks');
  await page.getByLabel('Статус').selectOption('done');
  await expect(page.getByRole('listitem')).toHaveCount(12);

  expect(urls.at(-1)).toContain('status=done');
});
```

## Ожидание ответа ловит не тот ответ, если его не уточнить

Метод `page.waitForResponse` возвращает первый подходящий ответ, а не тот,
который вызвало ваше действие.

```ts
test('ловушка: ответ уже летел', async ({ page }) => {
  await page.goto('/tasks');
  const [res] = await Promise.all([
    page.waitForResponse((r) => r.url().includes('/api/tasks')),
    page.getByLabel('Статус').selectOption('done'),
  ]);
  console.log(`  status=${new URL(res.url()).searchParams.get('status')}`);
});
```

```txt
  без ожидания списка: status=all
  ✓  1 tests/wait.spec.ts:3:5 › ловушка: ответ уже летел (210ms)
```

Ожидали ответ на выбор «готовые», а поймали ответ первой загрузки страницы.
Первый запрос ещё летел, когда тест начал ждать, и предикат согласился на него.
Выходов три, и они разной цены.

- **Уточнить предикат.** Условие `r.url().includes('status=done')` отсекает
  посторонний ответ.
- **Дождаться исходного состояния.** Ассершен на количество строк говорит, что
  первая загрузка завершилась.
- **Не ждать ответ вовсе.** Проверка на элемент ждёт результат, а не транспорт.

```ts
// то же самое без единого ожидания ответа
await page.goto('/tasks');
await page.getByLabel('Статус').selectOption('done');
await expect(page.getByRole('listitem')).toHaveCount(12);
```

Третий вариант и есть предпочтительный. Ответ сервера стоит ждать только тогда,
когда тест проверяет сам ответ: код состояния, тело, заголовки.

## Запись сетевого обмена заменяет сервер на следующих прогонах

Один прогон можно записать целиком: какие запросы ушли и что на них ответили.
Такая запись лежит в файле формата HAR (HTTP Archive), и дальше её подставляют
вместо сервера.

```ts
// запись: ходим на настоящий сервер и складываем ответы в файл
await page.routeFromHAR('har/tasks.har', { url: '**/api/**', update: true });

// воспроизведение: сервер больше не нужен
await page.routeFromHAR('har/tasks.har', { url: '**/api/**', update: false });
```

Записанный файл — обычный `JSON`, и его видно глазами. Ниже фрагмент настоящей
записи одного запроса.

```json
{
  "log": {
    "creator": {
      "name": "Playwright",
      "version": "1.63.0"
    },
    "entries": [
      {
        "request": {
          "method": "GET",
          "url": "http://localhost:3000/api/tasks?status=all&page=1"
        },
        "response": {
          "status": 200,
          "content": {
            "mimeType": "application/json"
          }
        }
      }
    ]
  }
}
```

Совпадение ищется строго по адресу и методу, а для `POST` — ещё и по телу
запроса. Поэтому запрос, которого в записи нет, по умолчанию обрывается: опция
`notFound` равна `abort`. Значение `fallback` пропускает такой запрос в сеть, и
это удобно на этапе, когда запись ещё неполная.

Запись стареет вместе с сервером, и это её главная цена. Обновляют её тем же
флагом `update: true`, а держат в репозитории рядом с тестом.

## Обработчик живёт до конца теста, если его не снять

Регистрация действует на весь тест, и это иногда лишнее.

```ts
test('первая загрузка пустая, дальше данные настоящие', async ({ page }) => {
  let calls = 0;
  await page.route('**/api/tasks*', async (route) => {
    calls++;
    await route.fulfill({ json: { items: [], total: 0, page: 1, pages: 1 } });
  }, { times: 1 });                          // сработает ровно один раз

  await page.goto('/tasks');
  await expect(page.getByRole('listitem')).toHaveCount(0);

  await page.getByLabel('Статус').selectOption('open');
  await expect(page.getByRole('listitem')).toHaveCount(20);
  console.log(`  обработчик сработал ${calls} раз`);
});
```

```txt
  обработчик сработал 1 раз, дальше запросы пошли в сеть
  ✓  3 tests/route.spec.ts:34:5 › times: 1 (70ms)
```

Снять обработчик руками помогают `page.unroute()` для одного правила и
`page.unrouteAll()` для всех сразу. У второго есть опция `behavior`: значение
`wait` дожидается уже начатых обработчиков, а `ignoreErrors` гасит их ошибки.

## Типичные ошибки

- **Подменять то, что тест проверяет.** Симптом: тест «проверяет вход», но при
  сломанной аутентификации остаётся зелёным.
- **Ставить общий обработчик после частного.** Симптом: частное правило
  перестало работать, потому что общее теперь идёт первым.
- **Ждать ответ без уточняющего условия.** Симптом: тест зелёный, но проверяет
  ответ предыдущего действия.
- **Забыть про `POST` при воспроизведении записи.** Симптом: список из записи
  подставился, а вход упал, потому что тело запроса не совпало.
