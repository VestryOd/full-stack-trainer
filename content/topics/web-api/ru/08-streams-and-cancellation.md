# Большие данные обрабатывают по частям и умеют отменять

Ждать, пока файл на несколько тысяч заметок загрузится и разберётся
целиком, — плохая идея: приложение молчит до самого конца, держит
весь текст в памяти дважды и не может остановиться на середине, если
пользователь передумал. Поток данных, `ReadableStream` и его
спутники, отдаёт данные кусками по мере готовности, а `AbortController`
даёт остановить обработку, не дожидаясь последнего куска.

## Дождаться файла целиком — не всегда разумно

Импорт архива заметок — сквозной пример этой статьи, и с большим
архивом наивный подход заметен сразу.

```ts
// Импорт архива: файл читается целиком, прежде чем можно
// хоть что-то показать пользователю
const text = await file.text();       // весь файл в памяти как строка
const notes = JSON.parse(text);       // и снова целиком, как массив объектов
notes.forEach((n) => saveNote(n));
```

На архиве в пару мегабайт это работает, но не даёт прогресса, держит
файл в памяти сразу в двух представлениях и не может остановиться
раньше, чем `JSON.parse` разберёт всё до последней запятой.

## `ReadableStream` отдаёт данные кусками произвольного размера

`file.stream()` возвращает поток данных, а не всё содержимое сразу —
читают его по частям, и размер каждой части браузер выбирает сам.

```ts
// Читаем архив по частям вместо file.text()
const reader = file.stream().getReader();
let chunk;
while (!(chunk = await reader.read()).done) {
  console.log(chunk.value.byteLength); // размер куска не гарантирован
}
```

Граница между кусками не совпадает с границами строк или записей —
кусок может оборвать JSON-запись прямо посередине. Ниже: одна и та
же запись archived-заметки разбита на два куска байтов, а после
пересборки в буфере восстанавливается верно.

```ts
// Проверено тем же стендом: строка "id":2 разрезана байтом ровно
// посередине, но буфер строк её всё равно собирает целиком
let buffer = '';
const results: Note[] = [];
for (const piece of ['{"id":1,"na', 'me":"a"}\n{"id":2,"name":"b"}\n']) {
  buffer += piece;
  const lines = buffer.split('\n');
  buffer = lines.pop()!;
  for (const line of lines) if (line) results.push(JSON.parse(line));
}
console.log(results.length); // 2 — обе записи разобраны верно
```

## `TransformStream` превращает байты в заметки, оставаясь конвейером

`TransformStream` встраивается между чтением и записью и меняет
данные на лету — в импорте архива он режет текст на отдельные
заметки построчно.

```ts
// Конвейер целиком: байты → текст → отдельные объекты Note
let buffer = '';
const lineSplitter = new TransformStream<string, Note>({
  transform(text, controller) {
    buffer += text;
    const lines = buffer.split('\n');
    buffer = lines.pop()!;
    for (const line of lines) if (line) controller.enqueue(JSON.parse(line));
  },
  flush(controller) {
    if (buffer) controller.enqueue(JSON.parse(buffer)); // последняя строка без \n
  },
});

const reader = file.stream()
  .pipeThrough(new TextDecoderStream())
  .pipeThrough(lineSplitter)
  .getReader();
```

Ни один шаг не забегает вперёд остальных: на конвейере из трёх
искусственных чисел, снятом тем же стендом, шаг трансформации
обработал одно значение, дождался, пока читатель заберёт результат,
и только потом взял следующее. Такое взаимное ожидание называют
обратным давлением (backpressure) — оно не даёт быстрому источнику
завалить медленного потребителя необработанными данными.

## `AbortSignal` обрывает конвейер, не дожидаясь его конца

Кнопка «Отменить импорт» должна остановить весь конвейер сразу, а не
только последний его шаг, — для этого `signal` передают в `pipeTo`.

```txt
Импорт архива идёт конвейером, а не одним куском
┌─────────────────────────────────────────────┐
│ Архив заметок: file.stream() отдаёт байты   │
└─────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────┐
│ TextDecoderStream: байты становятся текстом │
└─────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────┐
│ TransformStream: текст режется на заметки   │
└─────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────┐
│ Каждая заметка сразу пишется в IndexedDB    │
└─────────────────────────────────────────────┘
AbortSignal обрывает конвейер на любом из этих шагов
```

```ts
// Отмена вручную или по таймауту — какой сигнал сработает первым
const manualCancel = new AbortController();
cancelButton.onclick = () => manualCancel.abort('user cancelled import');

const signal = AbortSignal.any([
  manualCancel.signal,
  AbortSignal.timeout(60_000), // защита от зависшего импорта
]);

await readableNotes.pipeTo(writableNotes, { signal });
```

`AbortSignal.any` объединяет несколько сигналов в один: конвейер
остановится от того, что сработает раньше, — ручной отмены или
таймаута. Это не переиспользование примера из соседних тем: там
`AbortController` отменяет один `fetch`, а здесь один сигнал держит
сразу источник, трансформацию и запись одного конвейера.

## Уже обработанные заметки остаются, отменяется только остаток

Источник получает `cancel()` с причиной отмены, но заметки, которые
уже дошли до записи, никуда не деваются.

```ts
// Прогресс и честная остановка на середине конвейера
let imported = 0;
const writableNotes = new WritableStream({
  write(note) {
    saveNote(note);
    imported++;
    progressLabel.textContent = `Импортировано ${imported} заметок`;
  },
});

try {
  await readableNotes.pipeTo(writableNotes, { signal });
} catch (reason) {
  // reason === 'user cancelled import' — ровно то, что передали в abort()
  progressLabel.textContent = `Остановлено на ${imported} заметках`;
}
```

На шести уже записанных заметках отмена конвейера оставляет их
сохранёнными — это проверено тем же стендом на Playwright: `pipeTo`
прервался с причиной `'user cancelled import'`, а `WritableStream`
успел получить и записать всё, что дошло до него раньше отмены. Если
`abort()` вызвать со строкой вместо пустого вызова, эта причина
дойдёт до источника как есть, а не завёрнутая в `AbortError`.

## Типичные ошибки

- **Читать архив через `file.text()` вместо потока.** Симптом:
  интерфейс не показывает прогресс, пока не разберётся весь файл, а
  отмена ничего не останавливает, потому что уже поздно.
- **Считать, что кусок потока заканчивается на границе записи.**
  Симптом: `JSON.parse` падает на обрывке строки, потому что кусок
  байтов прервался посередине.
- **Отменять источник, не передавая `signal` в `pipeTo`.**
  Симптом: `reader.cancel()` вызван, а `WritableStream` продолжает
  дописывать то, что уже успело просочиться в очередь.
- **Откатывать уже сохранённые записи при отмене.** Симптом: пользователь
  отменил долгий импорт и получил пустой список вместо той части,
  что успела сохраниться.
