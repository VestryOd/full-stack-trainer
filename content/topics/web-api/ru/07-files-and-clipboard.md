# Файл попадает в приложение четырьмя путями

Кнопка выбора файла, перетаскивание, вставка из буфера обмена и
современный File System Access — четыре разных способа получить файл
от пользователя, и все четыре заканчиваются одним и тем же объектом.
Разница между ними не в результате, а в том, какого действия от
человека они требуют и что приложению разрешено делать с файлом
дальше.

## Все четыре пути заканчиваются одним и тем же объектом — `File`

`File` расширяет `Blob` и добавляет к нему имя, дату изменения и
размер — не важно, пришёл ли он из диалога выбора, буфера обмена или
перетаскивания.

```ts
// Классический выбор файла — точка входа, знакомая дольше всего
fileInput.addEventListener('change', async (e) => {
  const file = (e.target as HTMLInputElement).files![0];
  const text = await file.text(); // современный способ, без FileReader
  attachToNote(currentNoteId, { name: file.name, size: file.size, text });
});
```

| свойство `File` | что содержит |
|---|---|
| `name` | имя файла с расширением |
| `size` | размер в байтах |
| `type` | MIME (тип содержимого) — например, `image/png` — или пустая строка |
| `lastModified` | число — метка времени последнего изменения |

Методы `file.text()`, `file.arrayBuffer()` и `file.stream()` читают
содержимое асинхронно и не требуют старого `FileReader` с его
колбэками. Для больших вложений `file.stream()` — тема следующей
статьи, где файл читают по частям, а не целиком.

## Ссылка на объект живёт, пока её не отпустят

`URL.createObjectURL` даёт файлу адрес, по которому браузер может
показать его — например, превью вложения в заметке — без чтения
байтов в память приложения.

```ts
// Превью вложения к заметке: адрес выдаёт сам браузер
const objectUrl = URL.createObjectURL(file);
preview.src = objectUrl; // blob:http://localhost:8934/fffd41f1-...
// вид адреса снят тем же стендом на Playwright

// Когда превью больше не нужно — заметку удалили или закрыли форму
URL.revokeObjectURL(objectUrl);
```

Пока адрес не отозван, браузер держит файл в памяти, даже если
элемент `<img>` с этим адресом давно удалён со страницы. `revokeObjectURL`
— не оптимизация, а обязательная часть удаления вложения.

## File System Access даёт постоянный доступ, а не разовый выбор

Обычный `<input>` отдаёт `File` один раз, и без нового диалога
прочитать тот же файл снова нельзя. File System Access устроен
иначе: он выдаёт ручку — `FileSystemFileHandle`, — которую можно
сохранить и использовать в следующей сессии.

```txt
Ручка переживает сессию, обычный File — нет
┌────────────────────────────────────────────────────────┐
│ Пользователь открывает showOpenFilePicker()            │
└────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────┐
│ Приложение получает FileSystemFileHandle               │
└────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────┐
│ Ручку сохраняют в IndexedDB на будущее                 │
└────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────┐
│ В новой сессии: handle.queryPermission() перед чтением │
└────────────────────────────────────────────────────────┘
доступ к файлу приложение просит снова, а не выбирает заново
```

```ts
// Открыли файл один раз, сохранили ручку — доступ переживёт закрытие вкладки
const [handle] = await window.showOpenFilePicker();
await saveHandleForLater(currentNoteId, handle); // ручку кладут в IndexedDB

// В следующей сессии: сначала спрашивают разрешение снова
const status = await handle.queryPermission({ mode: 'read' });
if (status === 'granted') {
  const file = await handle.getFile();
}
```

На момент написания `showOpenFilePicker`, `showSaveFilePicker` и
`showDirectoryPicker` поддерживает только `Chromium` — проверяйте
актуальный статус в таблицах поддержки браузеров, а не по этому
тексту. Приложение, которому нужна ручка в любом браузере, обязано
предусмотреть классический `<input>` как запасной путь.

## Перетаскивание даёт файлы через `DataTransfer`, а не через клик

У события `drop` файлы лежат не в `event.target`, а в объекте
`DataTransfer`, который заодно умеет нести текст, ссылки и другие
данные.

```ts
// Зона перетаскивания вложений: без preventDefault на dragover
// событие drop вообще не произойдёт — так решает спецификация
dropZone.addEventListener('dragover', (e) => e.preventDefault());

dropZone.addEventListener('drop', (e) => {
  e.preventDefault();
  const files = Array.from(e.dataTransfer!.files);
  files.forEach((file) => attachToNote(currentNoteId, file));
});
```

```ts
// Что реально лежит в DataTransfer с одним перетащенным файлом —
// проверено на синтетическом объекте тем же стендом
console.log(Array.from(dataTransfer.types)); // ['Files']
console.log(dataTransfer.items[0].kind);     // 'file'
```

Список `types` не перечисляет MIME-типы файлов по отдельности —
он лишь сообщает категорию `'Files'`, если перетащили хотя бы один
файл. Настоящий тип узнают из самого объекта `File` после того, как
его достали из `dataTransfer.files`.

## Буфер обмена: чтение просит разрешение, запись — жест

Запись в буфер обмена и чтение из него подчиняются разным правилам:
запись достаточно вызвать из настоящего действия человека, а чтение
дополнительно требует разрешения `clipboard-read`.

```ts
// Вставка вложения из буфера обмена — например, скриншот
pasteZone.addEventListener('paste', async (e) => {
  const item = Array.from(e.clipboardData!.items)
    .find((i) => i.type.startsWith('image/'));
  if (item) attachToNote(currentNoteId, item.getAsFile()!);
});
```

```txt
Без жеста и без разрешения:
NotAllowedError: Failed to execute 'writeText' on 'Clipboard':
Write permission denied.

С разрешением на чтение:
clipboard.read() → ClipboardItem, types: ['text/plain']
```

Оба сообщения сняты тем же стендом на Playwright. Разрешение
`clipboard-read` по умолчанию в состоянии `prompt` — то же самое
состояние, что и у геолокации из первой статьи темы. Автоматизированная
среда строже к жесту, чем обычный браузер: в настоящем Chrome клик
по кнопке почти всегда достаточен для `writeText`, но полагаться на
это стоит, только проверив себя в целевом браузере.

## Скачивание результата — это ссылка с атрибутом `download`

Чтобы отдать пользователю файл обратно, не нужен отдельный API —
достаточно ссылки, у которой браузер сам откроет диалог сохранения.

```ts
// Экспорт заметки в текстовый файл
function downloadNote(note: Note) {
  const blob = new Blob([note.body], { type: 'text/plain' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = `${note.title}.txt`;
  a.click();
  URL.revokeObjectURL(url);
}
```

`showSaveFilePicker` из File System Access делает то же самое иначе:
пользователь заранее выбирает и имя, и папку, а приложение потом
дозаписывает в файл несколько раз подряд. Ссылка с `download` этого
не умеет — она создаёт новый файл при каждом скачивании.

## Что выбрать для вложения к заметке

| сценарий | подходящий путь |
|---|---|
| Кнопка «Прикрепить файл» | классический `<input type="file">` |
| Область, куда перетаскивают картинку | `DataTransfer` на событии `drop` |
| Вставка скриншота сочетанием клавиш | `clipboardData` на событии `paste` |
| Редактирование одного и того же файла много раз подряд | File System Access, с `<input>` как запасным путём |
| Экспорт заметки пользователю | ссылка с `download`, без лишних разрешений |

## Типичные ошибки

- **Не вызывать `preventDefault()` на `dragover`.** Симптом: событие
  `drop` не происходит вовсе, а браузер вместо этого открывает файл
  в новой вкладке.
- **Забыть `URL.revokeObjectURL` после удаления вложения.** Симптом:
  память приложения растёт с каждым открытым и закрытым превью.
- **Ждать разрешение на запись в буфер обмена, как на уведомления.**
  Симптом: код показывает диалог, которого никогда не будет —
  запись почти всегда решается жестом, а не диалогом.
- **Полагаться на File System Access без проверки поддержки.**
  Симптом: кнопка «Открыть и продолжить редактирование» молча не
  работает в браузере, где `showOpenFilePicker` не существует.
