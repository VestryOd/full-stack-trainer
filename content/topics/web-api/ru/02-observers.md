# Браузер сам сообщает, когда что-то меняется

Вместо того чтобы опрашивать элемент о размере или видимости каждые
сто миллисекунд, можно попросить браузер сообщать об этом самому —
такую подписку называют наблюдателем, или observer. Наблюдатели
решают четыре задачи: видимость элемента, его размер, изменения
разметки и замеры производительности. Эта статья разбирает, когда
срабатывает колбэк каждого наблюдателя и как не оставить его
работать вхолостую.

## Опрос в цикле проигрывает подписке на изменения

Опрос тратит время процессора на вопросы, ответ на которые почти
всегда один и тот же: «ничего не изменилось».

```ts
// Так подгружали ленту заметок раньше: спрашивали позицию
// последней заметки 10 раз в секунду, даже если никто не скроллил
setInterval(() => {
  const last = document.querySelector('.note:last-child');
  const rect = last?.getBoundingClientRect();
  if (rect && rect.top < window.innerHeight) {
    loadMoreNotes();
  }
}, 100);
```

Каждый вызов `getBoundingClientRect` заставляет браузер пересчитать
раскладку страницы, если она успела измениться. Делать это десять раз
в секунду ради события, которое случается несколько раз в минуту, —
чистые потери.

```ts
// То же самое через наблюдателя: браузер сам скажет,
// когда последняя заметка окажется в поле зрения
const io = new IntersectionObserver((entries) => {
  if (entries[0].isIntersecting) loadMoreNotes();
});
io.observe(document.querySelector('.note:last-child')!);
```

Колбэк наблюдателя вызывается только тогда, когда пересечение
действительно изменилось. Опрос исчезает вместе с `setInterval`, а
вместе с ним исчезает и лишняя нагрузка на раскладку страницы.

## Четыре наблюдателя решают четыре разные задачи

У каждого наблюдателя своя зона ответственности, и путать их — частая
ошибка на собеседовании.

| наблюдатель | что видит | задача в ленте заметок |
|---|---|---|
| `IntersectionObserver` | пересечение элемента с окном или контейнером | подгрузка при прокрутке до конца ленты |
| `ResizeObserver` | изменение размеров содержимого элемента | перестроить боковую панель при её растягивании |
| `MutationObserver` | добавление, удаление узлов и смену атрибутов | заметить, что сторонний виджет вставил свою разметку |
| `PerformanceObserver` | технические замеры: тайминги, долгие задачи | собрать реальные цифры без ручного опроса |

Первые три наблюдателя смотрят на разметку и раскладку страницы,
а четвёртый — на работу самого браузера. Подробный разбор долгих
задач и их влияния на отклик страницы — это тема Browser / JS
Runtime, а не этой статьи.

## Колбэк наблюдателя срабатывает не мгновенно и не в вашем коде

Колбэк наблюдателя никогда не выполняется внутри той же синхронной
функции, которая вызвала изменение.

```txt
Когда браузер вызывает колбэк наблюдателя
┌────────────────────────────────────────┐
│ Ваш синхронный код                     │
└────────────────────────────────────────┘
                     │
                     ▼
┌────────────────────────────────────────┐
│ Микрозадачи: колбэк MutationObserver   │
└────────────────────────────────────────┘
                     │
                     ▼
┌────────────────────────────────────────┐
│ Layout, затем ResizeObserver           │
└────────────────────────────────────────┘
                     │
                     ▼
┌────────────────────────────────────────┐
│ IntersectionObserver, затем кадр (rAF) │
└────────────────────────────────────────┘
                     │
                     ▼
┌────────────────────────────────────────┐
│ Отрисовка на экране                    │
└────────────────────────────────────────┘
ни один колбэк не выполняется внутри вашего кода
```

Порядок снят на Chromium 153 через Playwright 1.63.0 на macOS 18
сентября 2026 года: колбэк `MutationObserver` вызывается как
микрозадача, сразу после текущего синхронного кода, а
`ResizeObserver` и `IntersectionObserver` — уже на следующем шаге
рендеринга, до отрисовки кадра. У другого браузера порядок шагов
рендеринга может отличаться в деталях, но микрозадача всегда идёт
раньше рендеринга.

```ts
// Три синхронных изменения атрибутов дают ОДИН вызов колбэка
// с тремя записями внутри — проверено тем же стендом
const mo = new MutationObserver((records) => {
  console.log(records.length); // 3
});
mo.observe(el, { attributes: true });
el.setAttribute('data-a', '1');
el.setAttribute('data-b', '2');
el.setAttribute('data-c', '3');
```

Наблюдатель копит изменения и отдаёт их одним пакетом, а не вызывает
колбэк на каждое из них. Это защищает от лавины вызовов, если код
меняет разметку в цикле.

## Наблюдатель, который не отписался, — это утечка

Наблюдатель держит ссылку на элемент, пока вы явно не скажете ему
остановиться.

```ts
// Подгрузка ленты заметок: наблюдатель отключается сам,
// когда компонент со списком размонтирован
function watchLastNote(el: Element, onReach: () => void) {
  const io = new IntersectionObserver((entries) => {
    if (entries[0].isIntersecting) onReach();
  });
  io.observe(el);
  return () => io.disconnect(); // вызвать при размонтировании
}
```

`disconnect()` снимает все элементы разом, `unobserve(el)` — только
один. Без вызова любого из них наблюдатель продолжает держать
элемент и вызывать колбэк, даже когда лента заметок давно закрыта.

## Типичные ошибки

- **Создавать наблюдателя заново при каждом рендере.** Симптом:
  число активных наблюдателей растёт быстрее, чем число элементов на
  странице, и растёт с каждым обновлением списка.
- **Ждать от `MutationObserver` немедленного вызова.** Симптом: код
  читает разметку сразу после её изменения и не находит того, что
  туда только что вставил наблюдаемый скрипт.
- **Путать `contentRect` у `ResizeObserver` с размером всего блока.**
  Симптом: расчёты сбиваются на padding и border, потому что
  `contentRect` — это только область содержимого.
- **Не вызывать `disconnect()` при размонтировании компонента.**
  Симптом: колбэк наблюдателя продолжает стрелять для элемента,
  которого больше нет на странице.
