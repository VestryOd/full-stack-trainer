# Шаблон: квиз

Читать вместе с [`README.md`](./README.md) этой папки и `content/STYLE.md` §1–§11 (особенно §9 —
она целиком про квизы). Содержательная часть — какие задания — пишется отдельно.

## Куда пишется

`content/quiz/<topic-id>.json` — массив заданий:

```json
{
  "id": "<topic>-quiz-1",
  "topicId": "<topic-id>",
  "question":    { "en": "...", "ru": "..." },
  "options":     { "en": ["...", "...", "...", "..."], "ru": ["...", "...", "...", "..."] },
  "correctIndex": 0,
  "explanation": { "en": "...", "ru": "..." }
}
```

**Поля `difficulty` у задания нет.** Здесь оно стояло, и это было неверно: `QuizQuestion` в
`src/types/index.ts` его не объявляет, и ни одна запись ни в одном из существующих квизов его не
несёт (проверено по всем файлам, 0 из 1100+ записей). Найдено при генерации квиза `python`
в сентябре 2026: агент сгенерировал по корпусу и типу, а не по шаблону, и был прав.

Размер по сайту: **12–47 заданий**, медиана 26.5, 3–11 тысяч слов.

## Квиз оказался самым слабым слоем сайта, и ломается он по КОРРЕКТНОСТИ

Это не стилистика. Реальные дефекты, найденные аудитом:

- `quiz/algorithms` item 14 утверждал `fib(5)=8`;
- item 16 выводил O(n) и ставил ключ на O(n log n);
- `quiz/nodejs` item 12 и `quiz/css-html` item 26 **не имели правильного варианта вообще**;
- `quiz/nodejs` items 2 и 17 давали противоположные ключи на один вопрос;
- `quiz/css-html` — **13 из 30 объяснений противоречили своему же ключу**;
- `quiz/browser-runtime` item 10 отмечал `localStorage` правильным местом для токенов, а
  записи `q-3`/`q-12` того же топика — нет;
- `quiz/architecture` — 9 из 20 заданий про CQRS/Event Sourcing, которых нет ни в одной из
  восьми статей темы;
- `quiz/solid-grasp` item 25 содержал вариант «Robot should not throw errors that `Rectangle`
  doesn't» — `Rectangle` в этом задании не существует, копипаста из item 23.

**Поэтому корректность проверяется первой, а язык вторым.**

## `options` рендерятся как ОБЫЧНЫЙ ТЕКСТ

| Поле | Рендер |
|---|---|
| `question` | markdown |
| `explanation` | markdown |
| **`options`** | **обычный текст** |

`QuizCard.tsx` кладёт вариант прямо в кнопку. **Бэктики и `**` в вариантах печатаются
буквально.** По сайту так осталось около 132 вариантов — записанный долг.

Осторожно с разменом: снятие бэктиков открывает токены вроде `COPY` и `WORKDIR` для `to_prose`
и создаёт новые флаги нераскрытых аббревиатур, закрыть которые можно только глоссами **внутри
неверных вариантов**. Поэтому **пиши варианты без бэктиков сразу**, словами, а имена API — так,
чтобы они читались и без подсветки.

## Ключ

**Порядок вариантов из файла до читателя не доезжает ни на одном маршруте.** Проверено по коду:
`getQuizQuestions` в `src/lib/quiz.ts` заканчивается `sliced.map(shuffleOptions)`, и её зовёт
тематический маршрут; случайный маршрут перемешивает у себя в `RandomQuizClient.tsx`.

Следствия:

- **«Чинить» порядок ключей в файле не надо.** Замер `scripts/audit/quiz_bias.py` — источник
  истины; в `STYLE.md` §9.1 девять волн жили мёртвые числа, и агент, прочитавший их как текущее
  состояние, «исправлял» сбалансированное распределение обратно в перекос.
- **Но и циклом `0,1,2,3,0,1,2,3` писать не надо.** В 13 квизах из 20 так и вышло. Читателю это
  не видно, но файл — исходник, и рендеринг может измениться.
- Пиши ключ там, где он естественно оказывается, и в конце прогони `quiz_bias.py`.

**Правильный вариант не должен быть самым длинным** (§9.2). Причина перекоса, когда он есть:
только правильный вариант получает пояснительное «— because …». Убери его или добавь такое же
всем остальным. Текущий замер по сайту: правильный самый длинный в 14% заданий — при случайном
уровне 25% стратегия «выбирай самый длинный» проигрывает угадыванию.

**Никаких ссылок на позиции** (§9.3). «Вариант B», «Option 2» неверны по построению:
`shuffleOptions` переставляет порядок. Называй вариант содержанием: «вариант про `localStorage`».

## Объяснение

**Начинается с причины, а не с разбора чужих вариантов** (§9.4).

```
До:   Option [1, 2, 4, 5, 3] represents DFS in-order traversal, and the reversed options
      represent other traversal orders, not BFS.

После: The option [1, 2, 4, 5, 3] is a pre-order DFS: visit the node, then its whole left
      subtree, then its right subtree. The option [4, 2, 5, 1, 3] is an in-order DFS: left
      subtree, then the node, then right subtree. Neither is BFS, because BFS never goes deep
      before finishing a level.
```

Объяснение рендерится как markdown, поэтому в нём можно и нужно давать код в фенсе и глоссу
аббревиатуры.

## Квиз не имеет права противоречить статьям и банку той же темы

Проверяется **перед сдачей**, по трём источникам: статьи темы, банк вопросов темы, остальные
задания того же квиза. Это §9.5, и это самый частый класс реальных дефектов.

Заодно **квиз не должен спрашивать то, чего в теме нет**: 9 из 20 заданий `quiz/architecture`
были про концепции, отсутствующие во всех восьми статьях темы.

## Тематические дубли

Реальные замеры: в `quiz/solid-grasp` **13 заданий из 24 — тематические дубли** (четыре про
SRP, четыре про «внедри интерфейс» для DIP, три про вынужденную заглушку ISP); в `quiz/git` 20
заданий покрывали около 16 тем, `quiz-8` и `quiz-18` задавали дословно один вопрос, reflog был
покрыт четырьмя заданиями.

**Перед сдачей выпиши список покрытых тем и сверь с числом заданий.**

## Аббревиатуры в квизе

По §2.2 читатель видит задание целиком, поэтому **аббревиатура, стоящая в варианте, может быть
расшифрована в вопросе или объяснении того же задания** — это норма, а не остаток. Именно
поэтому у закрытых квизов счётчик показывает ненулевые числа: у `http-rest` весь остаток такой
(`SSE`, `CORS`, `URI` в вариантах при глоссе в вопросе).

Но **глосса должна существовать хотя бы в одном поле задания**, а не в другом задании.

## Проверка корректности перед сдачей

```bash
python3 scripts/audit/quiz_bias.py                 # аргумент пути игнорируется, печатает весь сайт
python3 scripts/audit/quiz_duplicates.py           # тематические дубли
grep -c -iE "wait, let me|I apologize|let me recalculate" content/quiz/<id>.json
grep -c -E "[Oo]ption [0-9A-D]|Вариант [0-9А-Г]" content/quiz/<id>.json
```

Плюс вручную, по каждому заданию: правильный вариант существует, ключ указывает на него,
объяснение не противоречит ключу.

## Чеклист квиза

- [ ] У каждого задания правильный вариант **существует**, и `correctIndex` указывает на него
- [ ] Ни одно объяснение не противоречит своему ключу
- [ ] Ни одно задание не противоречит статьям темы, банку темы и другим заданиям квиза
- [ ] Все спрашиваемые концепции в теме присутствуют
- [ ] `options` без бэктиков и `**` — они печатаются буквально
- [ ] Правильный вариант не самый длинный; длины сопоставимы
- [ ] Ни одной ссылки на позицию варианта
- [ ] Объяснение начинается с причины
- [ ] Список покрытых тем сверен с числом заданий, дублей нет
- [ ] Аббревиатура из варианта раскрыта в вопросе или объяснении **того же** задания
- [ ] Язык фенсов из тех, что зона реально использует
- [ ] `quiz_bias.py` прогнан, следов авторской работы нет
