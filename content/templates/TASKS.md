# Шаблон: задачи

Читать вместе с [`README.md`](./README.md) этой папки и `content/STYLE.md` §1–§11.
Содержательная часть — какие задачи — пишется отдельно.

## Куда пишется

`content/tasks/<topic-id>.json` — массив задач:

```json
{
  "id": "<topic>-t-1",
  "topicId": "<topic-id>",
  "difficulty": "junior | middle | senior",
  "title":               { "en": "...", "ru": "..." },
  "description":         { "en": "...", "ru": "..." },
  "starterCode":         "...",
  "solution":            "...",
  "solutionExplanation": { "en": "...", "ru": "..." },
  "tags": ["kebab-case"]
}
```

**`starterCode` и `solution` — простые строки, одна на обе локали.** Здесь раньше стояло
`{ "en": …, "ru": … }` — это было неверно, проверено по всем 243 записям всех восьми файлов
(волна 25). Оба поля подсвечиваются жёстко как `typescript`
(`src/app/tasks/[topicId]/[taskId]/page.tsx:51`), даже в задачах про CSS и HTML.

`difficulty` в файлах — `easy | medium | hard`, и значение печатается в бейдже как есть.

Сейчас на сайте 8 файлов, 243 задачи, 215 тысяч слов.

## Три поля, два разных рендера

| Поле | Рендер |
|---|---|
| `description` | **markdown** (`descriptionHtml`) |
| `solutionExplanation` | **markdown** (`solutionExplanationHtml`) |
| **`title`** | **обычный текст** (`{t(task.title)}` внутри `h1`) |
| `starterCode` / `solution` | подсвечиваются как код |

**В `title` бэктики и `**` печатаются буквально.** Пиши название словами:
не `` Реализуй `debounce` ``, а `Реализуйте debounce`.

**Форма названия — как в остальных названиях того же файла, а не одна на рубрику.** Замер волны
25: 174 номинативных названия («Реализация LRU-кэша») против 36 императивных. Императивен только
`react` (24 из 29) и `graphql` (6 из 10); `algorithms`, `css-html`, `javascript` и `testing` —
номинативны на 100%. Читатель видит список задач одной темы, поэтому согласованность нужна внутри
файла. Для нового файла бери императив на «вы».

**Аббревиатура в `title` допустима по §2.2 только с оговоркой:** детектор мерит поля по
отдельности, поэтому глосса в `description` флаг с названия не снимает. Либо раскрывай прямо в
названии («LRU Cache (Least Recently Used)»), либо не ставь акроним в название.

## Шаблон задачи

```markdown
title:  <Что сделать, одной фразой, без бэктиков. Императив на «вы».>

description:
<Что требуется — одно предложение.>

**Требования:**

- <Требование>
- <Требование>

**Дано:** <входные данные / что уже готово>
**Ожидается:** <наблюдаемый результат>

```ts
// пример вызова и ожидаемый вывод
debounce(fn, 100);   // fn вызовется один раз через 100 мс тишины
```

starterCode:
<Рабочий скелет, который запускается и падает на ассертах — а не заготовка с `...`.>

solution:
<Полное решение. Запускается. Все идентификаторы определены.>

solutionExplanation:
<ЛИД: почему решение такое — одно предложение.>

<Механика — короткими предложениями или списком.>

- **<Ключевое место решения>.** <Почему именно так.>

**Крайние случаи:** <что решение делает на границах.>

**Частая ошибка:** <одна конкретная>. <Симптом.> <Что делать вместо.>
```

## Что даёт 85% флагов и как этого не делать

`solutionExplanation` пишется как **одно длинное предложение, нанизывающее механику, оговорки и
вывод**. Это тот же определяющий дефект сайта — список, надетый на предложение (см.
[`README.md`](./README.md) §3).

**Правило:** лид — одно предложение, отвечающее «почему так». Механика — списком, если пунктов
три и больше. Крайние случаи — отдельным блоком. «Частая ошибка» — **самая короткая проза
объяснения, а не самая длинная** (§4.3); в 26 банках из 30 было наоборот.

---

## Код в задачах: он и есть содержание

- **`starterCode` запускается.** Заготовка, которая не компилируется, не даёт читателю точки
  входа. Скелет должен падать на проверках, а не на синтаксисе.
- **`solution` запускается и все идентификаторы в нём определены** (§6.2). Это рубрика, где
  такой дефект дороже всего: читатель копирует решение целиком.
- **Ожидаемый результат — в комментарии рядом со строкой** (§6.3): `console.log(x); // 6`.
- **Строка кода до 92 символов**, язык фенса указан верно.
- **`description` и `solution` не противоречат друг другу.** Если требование говорит «без
  внешних библиотек», решение их не использует.
- **`solution` решает именно то, что описано в `description`.** Проверяется чтением обоих
  подряд, а не по отдельности.

---

## Локали

- **Код в локалях не расходится по построению**: `starterCode` и `solution` — одна строка на обе
  локали. Здесь раньше стояло требование сверять их между локалями; проверять нечего.
- **`description` не теряет требований в одной из локалей** (§8.3). Реальный дефект в курсах:
  английский потерял число, которое было в русском. **По этой рубрике паритет замерен и держится:**
  ни одного текста с отношением слов `en/ru` вне 0.80–1.45, и 4 расхождения структуры на 486
  текстов — все инлайн-выделение в английском без пары в русском.
- Английский разбивается по своему лимиту 25 слов, не переводится дословно.

## Русский в задачах

Здесь концентрация англицизмов выше, чем в статьях, потому что текст плотно про код. Замер по
`content/tasks`: **54 апострофных формы из 226 по всему сайту** сидят в этой рубрике
(`content/tasks/nodejs.json` — 23, `testing` — 10, `typescript` — 10, `javascript` — 11).

Апострофных склонений не бывает: либо русский термин, либо английский без склонения. Проверка:
`grep -n "[A-Za-z]\+'[а-яё]\+" content/tasks/<id>.json`

## Чеклист задачи

- [ ] `title` без бэктиков и `**` — оно рендерится как обычный текст
- [ ] `description` содержит требования списком, «Дано» и «Ожидается»
- [ ] `starterCode` запускается; `solution` запускается, идентификаторы определены
- [ ] `solution` решает именно то, что просит `description`, и не противоречит его ограничениям
- [ ] Ожидаемый результат в комментарии рядом со строкой; строки ≤92
- [ ] `solutionExplanation`: лид — одно предложение; механика списком; «Частая ошибка» — самая
      короткая проза
- [ ] Крайние случаи названы
- [ ] Аббревиатуры раскрыты **внутри задачи** — её читают отдельно
- [ ] Код в локалях совпадает, различаются только комментарии; требований в обеих поровну
- [ ] Ни одной апострофной формы
- [ ] `block_width.py content/tasks/<id>.json` — ноль; флаги — ноль

## Замер этой рубрики

`coverage.py` её пока не учитывает. Флаги считаются так:

```bash
python3 - <<'PY'
import sys, json
from pathlib import Path
sys.path.insert(0, 'scripts/audit')
import readability_flags as rf
p = Path('content/tasks/<id>.json')
for r in json.loads(p.read_text(encoding='utf-8')):
    for field in ('title', 'description', 'solutionExplanation'):
        v = r.get(field)
        if not isinstance(v, dict):
            continue
        for loc in ('en', 'ru'):
            t = v.get(loc)
            if not isinstance(t, str):
                continue
            pr = rf.to_prose(t)
            n = (len(rf.find_abbreviations(pr, loc)) + len(rf.find_long_sentences(t, loc))
                 + len(rf.find_long_paragraphs(rf.blocks_of(t))) + rf.count_caps_emphasis(pr))
            if n:
                print(r['id'], field, loc, n)
PY
```
